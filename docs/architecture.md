# Architecture

Technical decisions the brief structurally couldn't hold: library choices, file formats, how ingestion triggers. Living; edited as work proceeds. A decision that is hard to reverse also gets an ADR in `docs/adr/`, and this file points at it.

## Decided

- Web technology, one codebase, packaged per device — ADR 0001.
- Annotations in the PDF; sidecar index for identity — ADR 0002.
- Phase 1 reading is Preview plus ingest; sync scope is the PDF folder only — ADR 0003. **Whatever already syncs the researcher's files syncs it; Vitrine never moves a byte** (#250, story KEEP-11): `sources/pdf/` is an ordinary folder — in practice a symlink to an iCloud or Dropbox folder (§ Vault layout) — and the app has no sync setting, no second machine to configure, and no code that copies a file anywhere. It cannot tell a file a sync client delivered from one the user dropped in: both are a watcher event on a folder it reads (§ Watcher and Ingest). A second machine is therefore the researcher's own arrangement, inspectable with the tools they already trust, and its failures reach the app only as rows § Loose Ends already carries — a conflict copy, a PDF that is gone. It is also why a run's linked Artifacts are checked at the moment they become evidence rather than assumed present (story TEST-13, beat 4 #171).
- The public site at tacomancy.com is authored and deployed from `tacomancy/tacomancy`, with a copy of this repository's `docs/reference/branding/` and `docs/reference/prototypes/` — ADR 0012, which supersedes 0004 and 0011 on where it lives. Vitrine's page is `/vitrine/`, its gallery `/vitrine/prototypes/`.
- Settings is a ninth screen, not one of the brief's eight Surfaces: where the vault is, where the PDFs are, what it talks to — statements about the arrangement, never preferences — ADR 0025, which supersedes ADR 0017 decision 3's rejection of the surface and makes the Credentials panel a section of it. § Settings.
- TypeScript end to end; Electron; React; the core is a local HTTP API the renderer and the iPad PWA are both clients of; a pnpm workspace of `packages/core`, `packages/renderer`, `packages/shell` — ADR 0005 (plus `packages/markdown`, ADR 0008). The detail that ADR leaves to this file:
  - **Build and dev:** Vite for the renderer, `electron-vite` driving main, preload, and renderer from one config — `packages/shell/electron.vite.config.ts`, with the renderer's root pointed at `packages/renderer` and output under `packages/shell/out/`. The core builds separately (`tsc` to `packages/core/dist`), because the shell spawns its entry as a file and must not bundle it. `pnpm dev` builds the core, then starts electron-vite; in development the window loads the Vite dev server for HMR, otherwise the core serves the bundle. Any build that is not the installed bundle uses `Application Support/Vitrine (dev)` as the core's state folder — the shell decides by `app.isPackaged` (the explicit `VITRINE_APP_SUPPORT_DIR` verification runs set still wins) — so a development build remembers and opens its own vault — the review snapshot — and never the real one unless it is opened deliberately; the packaged app alone owns `Application Support/Vitrine`. Two instances on one vault would be two watchers and two writers to the same `index.sqlite`.
  - **Packaging** (#142, from the research in #136): **electron-builder**, `--dir` target, arm64 only, `asar: false` — a plain `Vitrine.app`, nothing to host. The core is staged with `pnpm --filter core --prod deploy` (`packages/core` gains `"files": ["dist"]`) and carried as `extraResources` into `Contents/Resources/core` — as two FileSets, `stage/core` (dist and manifest) and `stage/core/node_modules`, because electron-builder drops a FileSet's root `node_modules` whatever its filter says (`app-builder-lib/src/util/filter.ts`); the staged `node_modules` is the point, and its relative symlinks into `.pnpm` survive the copy; the shell's core entry has one `app.isPackaged` branch (`process.resourcesPath` vs the workspace path); `asar` is off so the core reads `out/renderer` as real files and the ASAR question never arises. Bundle identifier `com.tacomancy.vitrine`, `productName: Vitrine`, the brand mark as the icon — the identifier is fixed now with intent because it becomes the Keychain and login-item identity later (BYOK, #139) and changing it after a key is stored orphans the key. **Unsigned and un-notarized**: a build made on this Mac is never quarantined, so Gatekeeper never evaluates it, and notarization is unavailable to anything but a Developer ID signature; leave `mac.identity` unconfigured (electron-builder skips signing when the keychain holds no identity; `codesign -dv` on the result then shows Electron's own prebuilt linker-signed ad-hoc signature with no Team ID, and `codesign --verify` fails on the resources — the executable is signed, the bundle is not sealed, and neither matters to a bundle that is never quarantined) and keep the documented ad-hoc recipe — `identity: "-"` plus the `disable-library-validation` and `allow-jit` entitlements — as the fallback if a Team-ID launch failure ever appears, never `hardenedRuntime: false`. **No updater**: every macOS auto-update path is signing-gated, so the update path is `pnpm package` at the root — core build → deploy → shell build → `electron-builder --mac --dir` (`npmRebuild: false`; the shell has no production dependencies to rebuild) → quit a running Vitrine (`osascript`, stated if it will not quit, never forced) → replace the bundle in `/Applications` → relaunch. Dragging the `.app` from `packages/shell/dist/mac-arm64/` is the manual fallback; manual packaging per Electron's own docs is the fallback if electron-builder's pnpm collector misbehaves. Not Forge: it owns `out` (electron-vite would move to `dist`) and wants `node-linker=hoisted` workspace-wide. The packaged app is the daily driver, `pnpm dev` is for building — so `Scripts/run-hidden.mjs` must drive the installed bundle as well as the dev build. The root `.gitignore`'s `build/` entry means electron-builder's `buildResources` directory is not `packages/shell/build/`. Signing is revisited on the first of: a Keychain-stored key needing a stable code identity, `openAtLogin`, auto-update, or a second Mac — none of them phase 1.

Anything that is not the installed bundle (`electron-vite dev`, a built shell under run-hidden, `electron-vite preview`) is dev. *Icon*: `packages/shell/resources/icon.svg` — the Case from `docs/reference/branding/assets/mark-case.svg` centred on a solid ink (`#09111D`) rounded square drawn to Apple's grid (1024 canvas, 824 pt square, ~185 pt radius; the mask is drawn in, never applied by the system), with BRAND.md's clearspace; a copy composed from the frozen asset, so the frozen tier is untouched and the site gets an issue for its copy. `resources/` is the `buildResources` directory; `packages/shell/stage/` (the `pnpm deploy` target) is gitignored. *Build identity*: `pnpm package` passes `--config.buildVersion=<git describe --tags --always>` — `beat-2-39-g5f08a59`, thirty-nine commits past the beat that shipped, where the bare short SHA it used to pass answered nothing a person asks of an installed build (#323); `--always` so a clone with no tags fetched still builds, saying a SHA, rather than failing at the packaging step. `-dirty` is appended when the tree has uncommitted changes, computed by the shell's own `buildVersion` resolver from `git status --porcelain` rather than taken from `describe --dirty`, which ignores untracked files, so one suffix has one source — `Scripts/package.mjs` imports `launch.ts` directly, which is why the root `engines` asks for Node ≥ 22.18 (type stripping on by default) rather than a copy of the two lines; `version` stays `0.0.0`; the standard About panel shows both. The tags it describes against are the shipped beats — `beat-1b`, `beat-1c`, `beat-2`, `beat-2b` — annotated with what shipped in the style of `v1-final` and `v2-design`, each on the last commit on `main` before its beat issue closed; the two older tags mark tree replacements and are a different thing. `beat-1c` is an ancestor of `beat-1b`, which is not a mistake: beats 1c and 1b overlapped and 1c closed first, so on `main` the packaging beat's last commit (#198) precedes the watcher beat's (#202). `git describe` names the nearest ancestor tag, so the line is right and only the *names* read out of the map's order — leave it true rather than tidying it into a lie. `packages/shell/package.json` gains `"author": "Sarah Lehman"` so the default copyright line reads right. *`pnpm package`* is `Scripts/package.mjs`, one command: core build → `pnpm --filter core --prod deploy stage/core` → `pnpm --filter shell build` → `electron-builder --mac --dir` → ask a running Vitrine to quit over `osascript` and wait up to ~10 s (whether it is running is read from `pgrep` on the installed executable's path, which needs no automation permission and never matches the dev Electron) → remove and copy (`ditto`) into `/Applications` so the bundle is never half-overwritten → `open`. If it will not quit the script says so and stops, leaving the bundle in `packages/shell/dist/mac-arm64/`. Flags: `--no-install` (build only, for driving the fresh bundle before installing it) and `--install-only` (skip the build steps; the retry after a refused quit). No gate before packaging — it is how a branch is tried, red tests included — and no backup of the previous bundle: rollback is a checkout and a rebuild, and a second `Vitrine.app` under the same bundle id would be the two-instances case above. *Verification*: `Scripts/run-hidden.mjs --app <path/to/Vitrine.app>` drives any bundle, the dev launch when the flag is absent; `--support` keeps defaulting to a temp folder so the remembered vault is never touched. *Tests*: unit tests for the pure resolvers (core entry from `isPackaged`/`resourcesPath`, the state-folder choice, the build-version string); the bundle's proof is a run-hidden PNG of the packaged app on the fixture vault, quoted in the PR. Nothing packaging-specific runs in CI (`pnpm package` runs every beat anyway) — revisited if a broken bundle ever goes unnoticed. electron-builder pulls in `electron-winstaller`, whose postinstall only fetches a Windows installer binary; `pnpm-workspace.yaml` declines that build explicitly. Adds no Loose Ends rows and no Home items.
  - **Tests:** Vitest, for `core` and `renderer` alike. `pnpm test` at the root runs five projects from `vitest.config.ts` — `core` (node), `markdown` (node; its tests live in `tests/` rather than `src/` because `src` compiles without Node types and the corpus is read from disk), `renderer` (jsdom, Testing Library, a fake tRPC link), `shell` (node; only the shell's pure choices — anything needing a running Electron goes through `Scripts/run-hidden.mjs`), `tooling` (the lint rules and the dependency-cruiser boundary rules) — and the `test` job in `.github/workflows/ci.yml` runs lint, typecheck, and that suite as the second required check beside `guidance`, on a `macos-latest` runner: the Watcher is FSEvents (ADR 0013), and Linux's recursive `fs.watch` is a different mechanism that goes deaf to a page the app has atomically replaced, so the gate has to run the platform Vitrine ships on (ADR 0029). The core is exercised in-process with `app.request(...)`, no socket. The end-to-end runner is chosen by the first slice for which a hidden CDP script is not enough — beat 1b's demo (an Obsidian edit reaching the Inbox) is driven by `Scripts/run-hidden.mjs`, its watcher tests run a real `fs.watch` on a temp vault with the settle window injectable, and its renderer tests fake the subscription as they fake the tRPC link; until then `VITRINE_SNAPSHOT=<png>` makes the shell render its window hidden, capture it, and quit, so a change can be seen without a window appearing; `VITRINE_SNAPSHOT_AFTER=<ms>` holds the capture long enough for a script on `--remote-debugging-port` to drive the page first (keys, typing, computed styles over CDP). `Scripts/run-hidden.mjs` wraps all of that; `docs/agents/run.md` is the procedure.
  - **RPC:** tRPC; the router type in `core` is the contract, imported type-only by `renderer`. Pushes the brief needs (ingest landed, Scout finished, Unmatched annotation surfaced) are tRPC subscriptions over SSE, so no WebSocket server. Server state in the renderer goes through tRPC's TanStack Query integration; UI state is React local state; no global store until a second surface needs one. The one piece of UI state that crosses components — the Question the capture line just wrote — is held by the window component and handed to the surface on screen, which invalidates `questions.list`, selects the row, and takes the keyboard (ADR 0010).
  - **HTTP server:** Hono, hosting the tRPC adapter, the renderer bundle for the iPad, and PDF bytes for the Reader. Handlers are testable with a `Request` and no socket. The core binds `127.0.0.1` on an OS-assigned port and mints a session token at start; `/trpc/*` requires it as a bearer header and answers 401 before any router code otherwise. The bundle at `/` is served without the token — a navigation cannot carry a header, and the bundle is public code, not vault data. The core sets the bundle's CSP (`default-src 'self'; img-src 'self' data:`) as a response header rather than a meta tag, so the same `index.html` works under the Vite dev server. CORS on `/trpc` is open because the token, not the origin, is the auth.
  - **Shell ↔ core ↔ renderer:** the shell reads port and token from the core's `ready` message over the `utilityProcess` channel and answers the preload's single synchronous IPC (`vitrine:session`) with them; the token never travels in `argv` or a URL. The preload exposes exactly `window.vitrine = { port, token }`. The same channel carries the Host (`CONTEXT.md`): the core sends `pickFolder` with an id, the shell shows `dialog.showOpenDialog` asked for `openDirectory` and `createDirectory` and replies `pickedFolder` with the path or null; what it asks for is `packages/shell/src/main/chooser.ts`, pure and pinned by a test, with the reason for each property (#267). Beat 4 adds the Host's second method, `pickFile` / `pickedFile`, for *+ artifact* on an Experiment page (`openFile`, one file, no filter — an Artifact is any file); a file dropped on the page reaches the core as its path through Electron's `webUtils.getPathForFile` in the preload, and the core copies it (ADR 0035). `File ▸ Open Vault…` calls `vault.pick` on the core as one more HTTP client; since the renderer has no push channel yet, a vault opened from the menu is shown by reloading the window — a vault switch discards every piece of window state regardless. **Quitting is a message, not a kill** (#276): `app.quit()` takes the `utilityProcess` with it, leaving the core only the `process.on("exit")` last resort, which cannot await and so splices nothing. So the shell's `before-quit` defers the quit, sends `close`, and quits again on the core's `closed` — or after five seconds, whichever first, because a quit that hangs is worse than a Revision that stays parked, and a parked one is not lost (§ Watcher and Ingest, External Position edits). The bounded wait is `packages/shell/src/main/close.ts`, pure and pinned by a test, as `chooser.ts` and `launch.ts` are; the core answers `closed` whether or not the close succeeded, since a core that cannot close must not be what stops the app from quitting. `RunningCore.close` drops the open sockets rather than draining them: `events.subscribe` is a subscription that ends only when the renderer does, and `server.close` waits for every connection, so draining would mean a close that never resolves. Pushes to the renderer (ingest landed, Scout finished, a vault switched) are one SSE subscription, `events.subscribe`, authenticated with the same bearer header the queries carry — ADR 0013, § Watcher and Ingest.
  - **Styling:** plain CSS with CSS Modules per component, importing `docs/reference/branding/tokens.css` unchanged. Not Tailwind: BRAND.md law 1 (semantic tokens, never ramp steps) is a lint rule on `--color-<ramp>-*` outside `tokens.css` — `tooling/eslint-plugin-brand`, on CSS ASTs via `@eslint/css` and on string literals in TS/TSX for inline styles, with its own RuleTester suite. `tokens.css` names no serif family; the renderer defines `--font-serif` in `global.css`.
  - **Charts:** `d3-scale`, `d3-array`, and `d3-shape` are the only chart dependencies; every mark is our own React SVG element, in `packages/renderer/src/charts/` (one component and one CSS Module per chart: matrix, scatter, line — the sparkline is the line at a smaller size; funnel bars and ranked lists are plain HTML). No charting library: ECharts and Nivo resolve colours to values in JavaScript, which cannot see `tokens.css` or its three theme states; Plot renders outside React; Visx would be a second abstraction over the same d3 scales (`docs/research/0134-charting-library.md`, decision #141). **Chart code never names a colour.** A scale's range is class names (`none`, `b1`…`b4` for the matrix's bins), applied as `className`, and the CSS Module binds each class to a semantic token — the same class paints the legend swatch — so the cascade gives every chart its dark, light, and `[data-theme]` states and the CSS-AST lint is the one that polices chart colour. To close the hole a `getComputedStyle`-to-hex shim would open, `tooling/eslint-plugin-brand` also forbids a colour literal — hex, `rgb()`/`hsl()`/`oklch()` — outside `tokens.css`, in CSS and in TS/TSX strings alike; that rule and a RuleTester case for a `var(--color-<ramp>-*)` JSX attribute land with the first chart (beat 8).
  - **Fonts:** bundled via `@fontsource` — Inter, IBM Plex Mono, Josefin Sans for the wordmark, and Source Serif 4 for questions and quotations, the role the prototypes drew and ADR 0004 asked this decision to settle. Nothing loads from Google Fonts in the app.
  - **Lint and format:** ESLint (typescript-eslint, type-aware) and Prettier, as the vendored `setup-pre-commit` expects — `pnpm lint`, `pnpm format`, `.prettierrc` per that skill; Prettier covers code only, prose and the frozen tier are ignored. dependency-cruiser in `.dependency-cruiser.cjs`, run by `pnpm lint:boundaries` as part of `pnpm lint`: the layering rules § Markdown's package rule names, each proved to fire by `tooling/dependency-cruiser/boundaries.test.js`. The entry-point rules `setup-ts-deep-modules` ships (root files public, subfolders private) are not adopted — every package is a flat `src/` behind `src/index.ts` — and restructuring toward them is a separate decision.
  - **Compiler:** `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`, `isolatedModules`, in `tsconfig.base.json` which every package extends. TypeScript stays on the 5.x line until typescript-eslint supports 6/7. Node is whatever the current Electron ships.
  - **Core lifetime:** the app's. No `launchd` agent unless daily Scouts prove they want one.
- One Markdown file per object, Kind in frontmatter, App state in `.vitrine/` — ADR 0006. The concrete layout is § Vault layout below.
- PDFium via WebAssembly in the core is the only thing that reads or writes a PDF; PDF.js in the renderer only draws pages; annotation identity is re-matched text first, geometry second, in five tiers — ADR 0007, accepted on the numbers `prototype/pdf-roundtrip` (#108) produced. The detail that ADR leaves to this file:
  - **Core engine:** `@embedpdf/pdfium` raw bindings (not `@embedpdf/engines`), in one `worker_thread` behind a job queue; one worker, not a pool. Appearance streams via its `EPDFAnnot_GenerateAppearance`, regenerated after every edit. Every save is a full rewrite (`FPDF_SaveAsCopy` with flag `2`) to a temp file, then renamed; incremental (flag `1`) is held in reserve for a file whose structure a rewrite would damage. Measured by the prototype, one highlight per write, `FPDF_LoadPage` on the page being annotated:

    | File | Size | Per incremental write | After five | Full rewrite | Time |
    | --- | --- | --- | --- | --- | --- |
    | Der Kiureghian 2009, page 1 (text, two-column) | 215 KB | 38 KB | — | — | — |
    | Der Kiureghian 2009, page 0 (text) | 215 KB | 58 KB | 508 KB | 219 KB | 3 ms |
    | Lewis 2021, page 0 (text, single-column) | 885 KB | 109 KB | 1.43 MB | 850 KB | 11 ms |
    | Scan of the same paper, 4 pages | 2.33 MB | 474 KB | 4.7 MB | 2.33 MB | 2 ms |

    The incremental save re-emits every object the page load pulled in (skipping text extraction saved 2 KB), so the cost is the page's fonts and streams and, on a scan, its image. The full rewrite keeps streams compressed and keeps `/ID[0]`.
  - **Renderer:** `pdfjs-dist` directly behind one component — canvas, text layer, Vitrine overlay. The engine's own rendering of text-markup and note annotations is suppressed; the overlay draws them from the core's index. Ink and shapes render from the PDF untouched.
  - **Annotation intent** (renderer → core): page index, geometry in PDF user space, kind, colour, note text. The core snaps geometry to its character boxes, derives the quote, writes the object, assigns the id. Selection text from the renderer is never stored.
  - **Written into the PDF:** `/NM` = sidecar id, `/T` = the user's name, `/CreationDate`, `/M`, `/AP`, standard `/Subj`. `FPDFPage_CreateAnnot` writes the object direct inside `/Annots`, not as `n 0 R`.
  - **Read back:** colour through the fork's `EPDFAnnot_GetColor` (and `EPDFAnnot_GetOpacity`) — stock `FPDFAnnot_GetColor` refuses once an `/AP` exists, and every annotation Vitrine writes has one.
  - The sidecar's fields and the matching tiers are § Annotation identity below.
- Markdown is located and spliced, never re-serialised; a closed set of write operations; Obsidian's grammar in a fourth workspace package, `packages/markdown`, shared by core and renderer; tag identity case-insensitive — ADR 0008. The detail that ADR leaves to this file:
  - **Locator:** `mdast-util-from-markdown` (micromark) with GFM and four extensions of our own — tags, wikilinks, block ids, `key:: value` inline fields — all in `packages/markdown`. Offsets are UTF-16 code units into the source string, which is what `String.prototype.slice` takes. `remark-stringify` is not a dependency.
  - **Cost per paragraph** is linear in its lines, by a patch to micromark (`patches/micromark@4.0.2.patch`, applied by pnpm on install; ADR 0019). Its text resolver merged the `data` fragments GFM's autolink literal splits at every word start with one splice per run — quadratic in a paragraph's lines, seconds for a note of some thousand unbroken lines inside the index build (#195, #196). `tests/outline.performance.test.ts` and `tests/inline-field.performance.test.ts` hold the bound; a micromark bump must carry the patch forward or drop it once upstream merges the same change.
  - **Frontmatter:** `yaml` (eemeli), `parseDocument` → `set` → `toString`. Known renormalisations: 4-space indent to 2, `[a, b]` to `[ a, b ]`. The fence is `---` at byte 0 (after a BOM if any), closed by `---`; a file whose frontmatter does not parse is *unreadable* for Kind purposes and the app never writes to it.
  - **Package rule** (dependency-cruiser, `.dependency-cruiser.cjs`): `core` and `renderer` may import `packages/markdown`; it imports neither (`markdown-imports-no-package`, by resolved path or by bare specifier), and no Node built-in (`markdown-no-node-builtins`; its `tsconfig.json` also compiles `src` with no Node types, so a `node:` import fails typecheck first). It builds with `tsc` like the core, because the core imports it at runtime from `dist`, and is the `markdown` project in `vitest.config.ts`.
  - **Writes:** § Markdown below — the eight operations, the re-apply, the verify step, and the file-level rules (temp file and rename; EOL, BOM, and trailing newline preserved; new files UTF-8, LF, one trailing newline).
- A `kind: question` file is read as found: frontmatter only, a missing `status` is open, a missing `question` or `captured` is Partial, a wrong value is Unreadable with its reason — ADR 0009.
- One recursive `fs.watch` over the vault root (libuv's FSEvents backend, no native module) plus one over the PDF folder's real path; every event is stat-and-compared, then hashed; a file is acted on once it has settled, and everything that settles together is one Ingest run; what the watcher missed, a stat-only sweep catches up — ADR 0013. The detail that ADR leaves to this file:
  - **Watcher:** `fs.watch(root, { recursive: true })` and, when `realpath(sources/pdf)` resolves outside the root, a second on that path with events rebased onto `sources/pdf/…`. No other symlink is followed. Entries beginning with `.` are dropped at the event level. Owned by the vault service: created by `open`, closed by the next `open` or exit; on `error` (including overflow) it is closed, reopened, and a full sweep runs. On open the order is *watch, then sweep* — and "watch" means *live*, not returned: `fs.watch` returns before libuv has created its FSEvents stream on its own thread, and the stream reports nothing earlier than its own creation, so `watchVault` touches a probe (`.vitrine/.watch`, a dot-entry nothing downstream sees) every 50 ms until an event arrives, then removes it and lets the sweep start (#188; ~10 ms on an idle Mac, bounded at 5 s). Silence past that bound is a watch that does not deliver, so `watchVault` *rejects* rather than hand back a watcher that is not watching; the vault service takes that as *not watching*, opens the vault anyway and sweeps it, and the silence reaches `vault.status` as the reason (#190; the path is covered by #272).
  - **Numbers,** all code: settle window 2 s (no events, and two stats agreeing on size and mtime); run window 5 s after the last file settles; the external-edit splice window is ADR 0006's 30 minutes.
  - **Hash:** SHA-256 via `node:crypto`, hex. Never computed for a file whose `blocks === 0 && size > 0` (evicted).
  - **Push:** tRPC `httpSubscriptionLink` with the `eventsource` v5 ponyfill, the bearer header set on its `fetch` — shipped by #188 and verified in the packaged renderer; the plain-Hono-SSE fallback was not needed. One stream, a discriminated union — § Watcher and Ingest.
- `index.sqlite` is the read path for every surface — lists, counts, backlinks, resolution — through Node's built-in `node:sqlite`; it lands with the watcher's Markdown consumer (beat 1b), holds the whole outline except body text, is refreshed per watcher batch in one transaction, and is dropped and rebuilt in the background on any schema mismatch — ADR 0014. The detail that ADR leaves to this file is § Index below.
- The first Scout beat is arXiv; a Scout's Filter is a hand-written Query plus the Questions it is Assigned to (no score behind "assigned"); Scouts run when due while the app is open; the Queue ships its two Lanes, the stack, keyboard triage, group-by-Scout, reject-this-run, and hand promotion, with everything that needs accept history or a second source on a named Wait list; health is derived from run rows — ADR 0016. The detail that ADR leaves to this file is § Scouts below.
- A Tag's Lexicon is derived from the titles and abstracts of the Tag's papers — recurring phrases, discounted by vault-wide frequency — with author keywords as extra votes when known and the user's Seeds and Exclusions applied; derived Terms are a projection in `index.sqlite`, only Seeds and Exclusions live in `lexicon.json`; one term set per Tag, compiled per Structured source as an OR of quoted phrases; every growth-rate measurement stores the query it was made with — ADR 0018. The detail that ADR leaves to this file is § Lexicon below.
- A Revision is one Markdown list item with its previous text indented inside it; a Research Question's prose sections are *Edited sections* the view replaces whole with `replaceSection`; supporting and opposing are the only two sides; a Research Question has `status: open | answered | abandoned` and resolves by write-back; a stub can be made by hand from the attach form; the window's location is the URL hash — ADR 0020. The detail that ADR leaves to this file is § Vault layout (Position history) and § Research Question view and triage.
- An Artifact is copied into the vault by the app, never out and never moved; the 25 MB threshold proposes stored or linked and the user decides per Artifact; a linked Artifact records the machine and a Fingerprint it was linked from, checked when it is attached as Evidence and never a refusal — ADR 0035, which adds `copyArtifact` to ADR 0008's closed set. The detail is § Vault layout (Experiment) and § Experiment view.
- The Vault editor is CodeMirror 6 behind a hand-rolled React wrapper; it opens any Markdown file in the vault, its whole-file save records Position Revisions itself and never refuses on shape, and a file changed on disk under a dirty editor is a non-modal line with *keep mine* / *take the disk copy* — ADR 0015. The detail that ADR leaves to this file is § Vault surface below.

## Vault layout

The shape ADR 0006 decided, in enough detail to write against. Conventions that hold everywhere: timestamps are ISO 8601 with local offset; links are wikilinks; app-owned fields are flat frontmatter keys; the app reads `tags:` and inline `#tag` but writes only `tags:`; `status: abandoned` keeps the file, and app-initiated deletes go to the macOS Trash. Every app-owned object carries `id:` (10 chars of base32, 50 random bits) and `kind:`.

```
<vault>/
  questions/     Question and Research Question notes
  hypotheses/    Hypothesis notes
  experiments/   one folder per Experiment: <name>/<name>.md plus stored Artifacts
  sources/       Source and Source stub notes, <citekey>.md
  sources/pdf/   the PDFs, <citekey>.pdf — the ONE synced folder (symlink to iCloud/Dropbox)
  notes/         Notes the app creates on request; the user keeps Notes anywhere
  .vitrine/      App state — see below
```

**Question** — `questions/<text, forbidden chars stripped, ≤80 chars>.md`: `* " \ / < > : | ?` and `# ^ [ ]` removed, whitespace collapsed, leading dots removed (a dot-entry is skipped on open), cut at 80 characters on a word boundary; the `id` when nothing survives; ` (2)`, ` (3)`, … on collision. Frontmatter: `id`, `kind: question`, `question` (exact text), `status` (open | promoted | answered | abandoned), `captured`, Provenance as four flat keys — `from` (a wikilink, or free text when `context: other`), `page`, `annotation` (block id, Sources only), `context` (reading | writing | ingest | resolving | pursuing | other) — plus `tags`, `related` (wikilinks added by the Link action; the only links Coverage counts on a Question), `promoted_to`, `answered`. `question:` is always double-quoted on write — deciding when a plain scalar is safe means carrying YAML's rules, and one wrong call makes a Question unreadable. Body: free; the answer when answered. Write-back from a Hypothesis whose loop is closed, when the Hypothesis was promoted from this Question, sets `status: answered`, `answered`, and appends one line — `Answered by [[hypothesis]] — falsified, <date>` — to the lead. It reaches no further than the object promoted from (ADR 0031 decision 8): a Hypothesis promoted from a Research Question writes to that page, below.

**Research Question** — same folder, file name suffixed ` (RQ)`, `kind: research-question`, `promoted_from`, `promoted` (timestamp), `status` (open | answered | abandoned — never `promoted`), `answered`, `tags` and the Provenance keys copied not re-derived; no `related:` — on a page that edge is the section. Body headings, in order, all written at promotion: `## Working answer`, `## Supporting sources`, `## Opposing sources`, `## Related questions`, `## Open threads`, `## Position history`. Promotion copies the Question's `related:` into `## Related questions` and leaves its body where it is: the first Revision's empty `from:` says the page started blank, and the history's base line ("promoted from a capture made while reading …") is derived from `promoted` and `promoted_from`, never written. Line grammars: a source line is `- [[citekey#^h12]] — why it is here`, and there is no third side (ADR 0020); a related line is `- [[question]] — note`; an open thread is a task-list line, `- [ ] …` ticked to `- [x] …` when resolved, never deleted. A Question captured on the page carries `from: [[<name> (RQ)]]` and `context: pursuing` and is appended to `## Related questions`. `## Working answer`, `## Open threads`, `## Related questions`, and — when a source is moved or detached — the two sources sections are *Edited sections* (`CONTEXT.md`): the view saves each with `replaceSection` as the user's own typing, and the app never rewrites them otherwise; a move is not a Revision. *Move* and *detach* (#219) name the line by its text, as a ticked thread is named, so a file edited underneath takes the write where it was meant — a text that is gone, or that two lines read, refuses rather than guessing which was meant; a move rewrites both sides, a detach only the one the line left, and a side whose heading has been retyped refuses in those words rather than letting `replaceSection` append that heading below `## Position history`. *Resolve* sets `status: answered` and `answered`, takes the Working answer as the answer, and writes back to the originating Question exactly as a Hypothesis does: `status: answered`, `answered`, and `Answered by [[<name> (RQ)]] — <date>` appended to the lead. *Abandon* on the page writes back the same way — `status: abandoned` on both, `Abandoned with [[<name> (RQ)]] — <date>` on the Question — and sets no `answered:` on either, as *drop* on a Question sets only its status; the date is in the line. `<date>` is the resolution's timestamp cut to its day (`2026-09-22`): the line is prose a person reads, and the timestamp is in the key. The two writes are the page's first, and the second is not rolled back if it fails — a page whose Question is gone stays resolved and the refusal is named on it. *Reopen* on the page sets `status: open` and touches nothing else: the body, the Position history, the Question's line, and the page's own `answered`, which stays for the same reason a Question's does; the Question's own reopen is the Inbox's. *Answer in place* on a Question appends the typed line to the lead and sets the same two keys; *drop* sets `status: abandoned`; *reopen* sets `status: open` and keeps the body, leaving `answered` where it is as the record of when the question was answered — no operation removes a key, and the Status is what says it is open again; *link* appends to `related`.

**Hypothesis** — `hypotheses/<claim at promotion>.md`, named by the Question's rule (forbidden chars stripped, whitespace collapsed, leading dots removed, 80 characters on a word boundary, the `id` when nothing survives), no suffix, refused rather than suffixed ` (2)` when the name is taken, and never renamed when the claim is revised (ADR 0031 decision 9). Frontmatter: `id`, `kind: hypothesis`, `promoted_from` (a wikilink to the Question or Research Question; absent on one written by hand), `promoted`, `tags` and the Provenance keys copied, not re-derived. Body headings, in order, all written at promotion: `## Claim` (the typed claim), `## Criteria` (empty), `## Design notes` (empty), `## Position history` (the claim's first Revision, `from:` empty). Each criterion is `### <criterion text> ^c<n>`, then `relationship:: confirming | falsifying | diagnostic`, then `outcome:: met | not met | inconclusive` **only once one is recorded** — no `outcome::` line is *Awaiting evidence* (ADR 0031 decision 2) — then Evidence lines `- [[experiment]] — what it shows for this criterion`, each Evidence whether or not its link resolves. A new criterion takes `^c` + one past the highest number in the file *or* named in `## Position history`, so a number is never reused (decision 3), and is appended at the end of `## Criteria`; the page draws falsifying criteria in their own band above the rest, which is layout, not file order. The label is drawn, never written: the Relationship's letter and the id's number, `F1`, `C2`, `D5`. Derived state is never written. Position history fields: `claim`, `design notes`, and `criterion <label>` for a criterion's whole block (text, Relationship, Outcome, Evidence) — the label as it stood, whose digit is the id. A text or Relationship change while Evidence is attached is written `· criterion C2 · edited after evidence`, a deletion found by the watcher `· criterion C4 · deleted after evidence`; neither collapses. Each move of the Derived state is its own entry, `· state`, `from:` the state it left, written by the write that moved it with that write's criterion Revision's own timestamp, directly above it — the pairing is what attributes the move to the criterion (spec #327 story 45), and sitting above keeps a later edit to that criterion from coalescing past the move (#334). An Override is `· override` with a mandatory `why:` and `from: inconclusive`; its void is `· override voided`, `from:` the Override's timestamp. The Hypothesis stores nothing about its loop: a Question promoted from carries `Answered by [[hypothesis]] — <result>, <date>` in its lead, a Research Question `- [[hypothesis]] — <result>, <date>` under `## Related questions`, where `<result>` is `supported`, `supported (override)`, `falsified` or `inconclusive`, and closing again appends, never edits.

**Experiment** — `experiments/<name>/<name>.md`, where `<name>` is the short name the user typed when making it, stripped by the Question's rule, refused rather than suffixed when taken, and never renamed by the app: the folder holds stored Artifacts, so a rename would move binaries and break embeds. Frontmatter: `id`, `kind: experiment`, `name` (as typed — the Display name), `status` (planned | running | complete | abandoned, hand-maintained; changing it is `setFrontmatter` and never a Revision), `created`, `from` (optional wikilink to what prompted it, drawn as *came from*; never touches that object's Status — an Experiment is not a Promotion), `tags`. No `ran_at`. Body headings, in order, all written at creation: `## Purpose`, `## Design`, `## Where it ran`, `## Artifacts`, `## Observations`, `## Position history`. Positions are `design` and `observations` only; `## Purpose` and `## Where it ran` are Edited sections with no Revision. `## Where it ran` is `label: value` lines whose labels are the user's own (`repo`, `commit`, `entry`, `config`, `w&b`, `out` are what the page suggests); the Experiment Inbox's *project* facet reads a `repo:` line when present. `## Artifacts` is one list item per Artifact in the user's order, stored and linked alike: stored `- ![[plot.png]] — caption` with the file in the same folder, linked `- <file> — <path or URL> · <size> · <date> · <machine> · <fingerprint> — <description>`, where `<fingerprint>` is `<size>:<mtime>:<sha256 of first and last MiB, first 12 hex>` and `<machine>` the computer name (ADR 0035 decision 5). A file in the folder with no line is drawn *in the folder, not on the page* and offered *show it here*. Evidence attachments are recorded on the Hypothesis side only; the Experiment page reads them back from the Index's links out of `## Criteria` blocks. A Question captured from the page carries `from: [[<name>]]`, `context: observing`, and writes nothing onto the Experiment.

**Source / Source stub** — `sources/<citekey>.md`, `kind: source | source-stub`. A stub is written by a Scout's *accept* or by hand from a Research Question's attach form (title, authors, year, URL — the only hand path until Scouts land). Frontmatter: `citekey` (`<surname><year>`, ASCII-folded, lowercase, `a`/`b`… on collision; first word of the title when authors are missing), `title`, `authors`, `year`, `venue`, `doi`, `url`, `keywords` (author-supplied, when known — filled by a Structured source that returns them or typed; one input to the Lexicon, never the only one, ADR 0018), `pdf` (file name under `sources/pdf/`; absent on a stub), `origin_scout` (Scout id), `origin_question`, `origin_retroactive`, `appearances` (every URL Corroboration merged). Body: the user's notes, then an app-owned `## Annotations` section rewritten whole on every Ingest — one block per Annotation in page order:

```
- p.<n> · "<quote>" ^h<n>

  <the note text, indented two spaces>
```

The blank line is load-bearing and settled by observation, not taste (#164, corpus rows B4–B5): without it the note continues the item's one paragraph, the `^h<n>` sits mid-paragraph, and Obsidian indexes no block at all — `[[citekey#^h12]]` then hovers *Unable to find "^h12"*, which is ADR 0006 decision 6 failing silently. With it the id ends its paragraph, the block is the whole item, and the hover is the quote and then the note. An Annotation with no note is the quote line alone; a note that runs to several paragraphs keeps them, each indented two spaces, as a Revision's `from:` text does. The id is on the quote line rather than after the note so that no amount of note text can unseat it. Ids are `h` + a per-Source counter, never reused. Unmatched blocks stay, marked `(unmatched)` until resolved; *drop the links* marks the block `(gone)` and leaves it forever rather than editing the user's notes. Either marker goes on the quote line before the id, which keeps the id last (B5d). A Removed annotation's block (ADR 0007: unlinked, and gone from the file) is deleted; its number is never reused. Ink and shape annotations have no block.

**Position history**, in every kind that has one — newest first, one list item per Revision (ADR 0020):

```
- 2026-08-05T14:22:00+02:00 · working answer
  why: Cordi's funnel plot — the effect is mostly small-study bias. [[cordi2021#^h12]]
  from:
    Probably both, but the dissociation designs that could separate them are
    underpowered. The strongest case ...

    A second paragraph, still indented four spaces.
- 2026-07-02T09:10:00+02:00 · working answer
  from:
```

The first line is the timestamp and the field; `why:` (optional, one line, links inline) and `from:` are continuation lines indented two spaces, and `from:`'s text — the full previous text — sits one level further in so blank lines stay inside the item. An empty `from:` means the field was empty before. A coalesced entry carries the timestamp of the *latest* save in the window and the `from:` of before the *first*: "by this time the answer had moved from X". A why added later, from the history view, rewrites the owned section whole (`replaceSection`); an entry carries no id — its timestamp is its identity. Anything in the section that does not parse as an entry is left in place and reported as a shape problem. Edits to one field within 30 minutes coalesce; a why or a criterion edit after Evidence exists closes the entry early, and the latter is written as `· edited after evidence` permanently. Edits made in Obsidian are detected by the watcher and recorded the same way, spliced once the file has been quiet (§ Watcher and Ingest). Pressure valve if a page's history ever dominates it: entries older than a threshold move to `.vitrine/history/<id>.md` with a one-line pointer.

## Annotation identity

The shape ADR 0007 decided. The sidecar stores **raw** values; every rule below that compares them is code, so tuning never migrates a Source.

**`.vitrine/annotations/<source-id>.json`**
```
pdf                       file name under sources/pdf/
file                      { size, mtime, hash } of the PDF as last ingested or last written — § Watcher and Ingest
document_fingerprint      { id: trailer /ID[0], pages, page_words[] } — pages changed, or any page's word-set similarity below the threshold, is a document-changed event; id equal is a fast "same file", id different means nothing (PDFKit replaces it on every save)
reading_position
next_block                the per-Source ^h counter; never reused, not even after removal
annotations[]
  id                      what /NM carries when Vitrine wrote the object
  block                   h<n>
  kind                    highlight | underline | strikeout | squiggly | text | freetext | ink | stamp | shape (Square, Circle, Line, Polygon, PolyLine)
  page                    0-based index
  quads[]                 8 numbers each, PDF user space, as written (Preview's verbatim; Vitrine's snapped)
  quote                   engine-extracted text under the quads; for text/freetext the /Contents; empty on ink, shape, and image-only pages
  note                    /Contents on markup kinds
  question                the Question this annotation spawned under the `Q:` convention, once; never a second
  color                   the PDF's /C verbatim
  previous_quote, changed_at   one level only, set by a geometry-tier match
  matched_by              object | text | text-moved | geometry — how the last Ingest found it
  last_matched
  removed_at              set when an unlinked identity failed every tier; the entry stays so the block is never reused
  unmatched_since         set when a linked identity failed every tier; cleared by relink / drop / treat-as-new
  gone_at                 set by *drop the links*: the Tombstone. The entry is skipped by every later Ingest, its block stays `(gone)`, and its links keep resolving
```

**Kinds and what they get.** Markup and notes: identity, a `^h<n>` block, link target, `Q:` carrier. Ink and shape: identity and a count on Ingest; no block, never a link target or `Q:` source. Kind *families* for matching: markup (the four text-markup kinds), note (text, freetext), ink (ink, and stamp — what iPadOS Markup writes a pencil stroke as: an `/AP` plus PencilKit data, no `/InkList`; identity from `/Rect`, rendered from its `/AP`), shape.

**Normalisation** (code, applied at compare time to both sides): Unicode NFKC; join a hyphen at a line end to the next line's first word; collapse whitespace; case-fold. Ligatures fall out of NFKC. PDFium already merges a hyphenated line and flags the hyphen glyph (`FPDFText_IsHyphen`), and its character order is reading order, so a quote across a column break reads in order.

**Quote derivation** (code): a glyph is under a quad when ≥ 50 % of its tight box lies inside it. Checked on the prototype against quads PDFKit and the iPad wrote, across a hyphenated line break and a column break; the one known cost is a sideways nudge over a narrow edge glyph, which gains or loses that glyph and sends the match to tier 4 (ADR 0007 Consequences).

**Document fingerprint** (code): `page_words[n]` is the sorted set of ≥4-letter words on page *n* after normalisation; two fingerprints are the same document when page counts agree and every page's Jaccard similarity is ≥ **0.9**. Measured across a PDFKit save: ≥ 0.953 on every page (the worst is a math-heavy one); ≤ 0.24 between neighbouring pages. Per-page text hashes were the first design and changed on 7 of 8 pages across the same save.

**The tiers, in order, per previously known identity against the annotations now in the file:**

1. **object** — an annotation carrying our `/NM`, same kind family. Wins only if its normalised quote equals ours; otherwise fall through. PDFKit drops `/NM`, so this fires for Reader-only Sources.
2. **text** — same page, same kind family, normalised quote equal.
3. **text-moved** — any page, same kind family, normalised quote equal; page updated. Normally only reached after a document-changed event.
4. **geometry** — same page, same kind family, quad overlap (IoU over the union bounding boxes) ≥ **0.4**. A match here with a different quote records `previous_quote`. The prototype started at 0.6, which separates edited from adjacent but rejects the two most ordinary edits that change a quote; adjacent same-line highlights would need to overlap by ~29 % of their combined extent to reach 0.4. Measured on an 8.2 pt / 10.5 pt-leading column and a 10 pt / 12 pt one:

   | Case | IoU | IoU |
   | --- | --- | --- |
   | adjacent lines | 0.000 | 0.048 |
   | same line shifted one line down | 0.000 | 0.044 |
   | same highlight extended by ~10 glyphs | 0.869 | 0.873 |
   | same highlight nudged 1.5, −2 pt | 0.601 | 0.709 |
   | same highlight cut to its left half | 0.500 | 0.500 |
   | same highlight extended to the next line | 0.438 | 0.524 |
   | same highlight extended to three more lines | 0.206 | 0.273 |

5. **Unmatched** if the identity has inbound links (a backlink to `[[citekey#^h<n>]]` in `index.sqlite`, or a Question whose `annotation:` names it); **removed** otherwise. Because `index.sqlite` is disposable (ADR 0006), *removed* is concluded only against an index known to be current for this vault (`current()`, § Index) — Ingest refreshes it before this tier runs — and an identity whose links cannot be established is Unmatched, never removed. The cheap failure is a decision; the expensive one is silent link rot (`design-brief.md` § Annotation storage).

At any of tiers 2–4, several candidates are broken by quad overlap — the highest wins, comparing quads across pages as if on one page at tier 3 — and an unbroken tie is Unmatched. Each candidate can be claimed once; two identities claiming one candidate are both Unmatched, linked or not: ambiguity is a decision, so this is the one way an unlinked identity reaches the panel. The contested candidate is held with them — it is not counted as new — so resolving the row can relink it. Tombstones (`gone_at`) take no part in matching. Annotations left unclaimed are **new**: a fresh id and block, and a Question if the note begins `Q:`. A changed `document_fingerprint` runs the same tiers document-wide and groups every resulting Unmatched row under one event with batch resolutions.

**Ingest summary line:** `N new · N questions · N removed · N could not be re-matched` — the panel opens only when the last is non-zero (brief § Ingest review).

## Markdown

The shape ADR 0008 decided, in enough detail to write against.

**What the locator returns for one file** — an *outline* (`outline(source)` in `packages/markdown`): the frontmatter range and its parsed Document, or the block's range and the reason when `yaml` cannot read it, with the rest of the outline still returned; headings (level, text, range of the heading line, range of the section body to the next heading of equal or higher level); block ids (id, the block's range, the marker's range); wikilinks and Markdown links (target, heading path, block id, alias, embed flag, range); tags (canonical form, form as written, source `frontmatter | inline`, range); inline fields (key, value, range, the value's range, and the `###` they sit under); list items with ranges, from which the core's Position history module reads Revisions. Everything Vitrine-specific — which sections are owned, what `^c<n>` means, the Revision line grammar — is applied by the core's per-Kind modules to this structure. Offsets are UTF-16 code units into the string as handed in, a BOM included: `source.slice(start, end)` is every node's text.

The package's exports, each a public surface: the grammar functions — `parseTag`, `canonicalTag`, `isTagCharacter`, `parseWikilink`, `parseMarkdownLinkTarget`, `parseBlockId`, `isBlockIdCharacter`, `parseInlineField`, `isInlineFieldKeyCharacter`, `locateFrontmatter` (the fence rule, for `questions.list` to re-base onto) and `BOM`; the micromark syntax extensions with their `mdast-util-from-markdown` halves — `tags`, `wikilinks`, `blockIds`, `inlineFields`, plus `math`, which makes `$…$` opaque so a `#` in inline math is not a tag (T3i) and produces no node; `outline`; and the outline types. Calls the locator makes that the brief and the corpus leave open, settled here: only top-level headings are headings — one inside a callout or a list is not a section; a heading's `text` is its source text with the markers and a trailing `^id` removed, the id reported beside it; the section body starts after the heading's line ending and ends where the next heading of equal or higher level starts, so it is the exact splice target for `replaceSection`; a `^id` names its paragraph, the list item or callout the paragraph is in, the heading whose line it ends, or — alone on a line — the block above it, and a `^id` that is not at the end of its paragraph is prose; `links` holds internal links only (a destination with a scheme is not indexed, as Obsidian's cache does not); an inline field is `key:: value` at the start of a paragraph line — a list item's first line included, a heading or a callout line not — with the value tokenized as text so a link or tag inside it is still found; a `tags:` list entry is split at commas without trimming and any piece with whitespace is `invalid` (which is how `- alpha, beta` counts `alpha` alone, F2b, and `[machine learning, other]` counts `other`, F8), while the legacy scalar `tags: a, b` splits at commas and whitespace both; a `tags:` entry may carry a leading `#`.

**Write operations** — the closed set. Anything else reopens ADR 0008, as ADR 0035 did for `copyArtifact`.

```
setFrontmatter(keys)                    one or more keys; order preserved; new keys appended; never removes
setInlineField(blockId, key, value)     outcome:: / relationship:: under a ### … ^c<n>; the value range only
replaceSection(name, body)              an owned section whole: ## Annotations; ## Position history for the pressure valve
                                        and for a why added after the fact; an Edited section as the user's own typing
prependEntry(section, entry)            a Revision into ## Position history, newest first
appendToSection(target, line)           a line at the end of a ## section or a ### block: Evidence under ^c<n>,
                                        an Artifact line, a source line; `lead` = the body before the first ##,
                                        which is where the write-back line goes (end of file on a Question)
replaceFile(content, basedOn)           the Vault editor's save, and nothing else; the user's own typing
createFile(path, content)               a new object or an app-created Note, written whole
copyArtifact(source, experiment)        a file copied into experiments/<name>/ beside an Artifact line, the one
                                        write whose bytes are not Markdown; never out, never a move (ADR 0035)
```

A write = `{ operations[], basedOn: <content hash> }`. Before writing: re-hash; on mismatch re-read and re-apply the operations to the new content; splice — the frontmatter as one splice, then each section operation located against a fresh outline of the result, so two aimed at one spot land in operation order (#122; ADR 0008's "highest offset down" holds for the targets within one outline, and this is how the same guarantee is kept when a target is an insertion point); re-parse the result and verify — frontmatter parses, `kind` unchanged, each owned section present exactly once, block ids the app depends on present; write temp + rename. Re-apply impossible or verification failed → not written, surfaced with the reason. `replaceFile` skips the re-apply (there is nothing to re-apply) and refuses on a hash mismatch, which the editor surfaces as "changed on disk". Notes are written only by the editor, whole.

**Owned sections:** `## <name>` exact, case-sensitive, level 2. Absent → appended after a blank line at end of file. Duplicated → the first is owned, the second untouched, the duplicate surfaced as a shape problem.

**Shape problems:** a `kind:` file missing structure its Kind expects — no `## Criteria` on a Hypothesis, a `###` under `## Criteria` without `^c<n>`, an owned section duplicated on a Kind that owns it, an `outcome::` or `relationship::` outside its vocabulary — is reported in the same channel as *partial* and *unreadable* (#105) and derived state is computed from what parses. Each is `{ path, kind, problem, block? }` (`problem` ∈ `criteriaMissing | criterionWithoutId | ownedSectionDuplicated | fieldOutsideVocabulary`; `block` the `^c<n>` of a criterion field, the heading text of an id-less criterion, or the name of the duplicated section), `kind` being the file's Kind; a file with no `kind:` or an unknown one has no shape to fall short of. A field outside its vocabulary reads as absent on the criterion, so the derived state is the same *inconclusive* an unset field gives, with the row saying why.

**`vault.outline(path)`** (`packages/core/src/vault-files.ts`, #119): the core reads the file, strips a BOM and records it with the EOL and trailing-newline choice in `file` for the writer to restore — so every offset is into the BOM-less text the writer splices — outlines the rest through the package, and answers `{ readable: true, path, kind, hash, file, outline, criteria, shape }` or `{ readable: false, path, reason }`. `hash` is the SHA-256 of the bytes on disk, what a write is `basedOn`. `path` is vault-relative whether the caller passed a relative or an absolute one, as the index keys it; a path outside the vault, a dot-entry, a symlink that leaves the vault, or a non-Markdown file is a typed input error (`outsideVault`, `notMarkdown`), not an unreadable file. `outline.frontmatter` carries the plain `value` in place of the `yaml` Document; a frontmatter block that does not parse, or is not a map, makes the whole file unreadable (ADR 0009 decision 5). `criteria` is the Hypothesis's `### … ^c<n>` list — id, text, `relationship`, `outcome` — read only inside `## Criteria`, empty for every other Kind. Beat 1b re-assembles the same shape from the index.

**The write API** (same module, #121): `write(vaultPath, path, { operations, basedOn })` runs the protocol above for the splicing operations and answers `{ written: true, hash, content }` or `{ written: false, reason, detail }` with `reason` ∈ `changedAndUnreapplyable | verificationFailed | changedOnDisk | noFrontmatter | unreadable | alreadyExists`; an I/O failure at the rename is a `writeFailed` VaultError, as at capture. `setFrontmatter` is `{ keys?, addTags? }`: keys through `yaml`'s Document with `lineWidth: 0` so an untouched long scalar is never folded; every `setFrontmatter` in one write edits one Document, so the frontmatter is one splice. `addTags` skips a tag the file already carries under any casing (by canonical form), so the writer never introduces a variant of a tag the user has — ADR 0008's rejected "write tags in canonical lowercase", applied to the one case where writing verbatim would still add a variant. Verification (#121, completed by #122): the result parses, `kind` is unchanged (a file that had none gets none this way), every `##` section an operation targeted is present exactly once — or as many times as before, when the file already had a duplicate, which is reported on the read and on the write's result rather than refused (ADR 0008 decision 10) — every block id an operation depends on is still there, and no shape problem is newly introduced. A path is refused through a symlink on the way to it whether or not the file exists yet, so `createFile` cannot land outside the vault through a linked folder. `replaceFile(vaultPath, path, content, basedOn)` and `createFile(vaultPath, path, content)` are exported beside it; `replaceFile`'s fence (the Vault editor only) is its doc comment. No router procedure writes yet.

**The section operations** (#122), each located afresh against the file's current outline — the frontmatter is one splice, then each section operation is applied against a fresh outline of the result, so two operations aimed at one spot (two Revisions prepended in one write) land in operation order. `replaceSection(name, body)` replaces the heading's body range — after the heading line, up to the next heading of level ≤ 2 or the end of the file — with one blank line after the heading and one before the next heading, the app's convention inside a section it owns; the heading line is untouched. `prependEntry(section, entry)` inserts directly under the heading line, after the blank line the file keeps there if it keeps one, so the existing first entry becomes the second byte-identical; an empty section gets the blank line. `appendToSection(target, line)` takes `{ section }` (a `##`), `{ block }` (a `###` carrying that block id — `blockNotFound` otherwise), or `"lead"` (the body before the first `##`; at the end of the file when there is none), and inserts after the target's last non-blank line — directly below it when that line is a list item and so is the new one, so Evidence and source lines read as one list beside the user's, otherwise after a blank line, so the line neither continues the user's paragraph nor unseats a `^id` at the end of it; an empty section gets the blank-line convention; a blank lead puts the line above the first `##`. `setInlineField(blockId, field, value)` needs a `### … ^c<n>` inside `## Criteria` (`notACriterion` otherwise, ADR 0006 decision 2) and replaces the field's value range only; a criterion without that field gets the line, after its other field or directly under the heading. An absent `##` target of any of the three section-named operations is appended at the end of the file after one blank line, never at a canonical position, and a heading the user renamed counts as absent (ADR 0008 decision 10); the first of a duplicated pair is the app's. A section body or line is composed by the app in LF and written in the file's line endings; the trailing-newline choice is restored after the last splice, so a file without one stays without one whatever was appended. The write's result carries `shape` — the file's shape problems as written, which is how a duplicate the write worked around reaches the caller. `nextBlockId(outline, prefix)` gives the app's next `h` (or `c`) id for a file: one above the highest `^<prefix><digits>` already there, the user's hand-written ones included, `<prefix>1` when there is none (ADR 0008 decision 11). Refusal reasons now also include `notACriterion` and `blockNotFound`; under re-apply a target that is gone from the changed file is `changedAndUnreapplyable` as before.

**Tag grammar** (Obsidian's, `help.obsidian.md/tags`): after `#`, letters, digits, `_`, `-`, `/`, and other commonly accepted Unicode including emoji; no spaces; at least one non-digit. Not a tag inside a fenced or indented code block, a code span, a wikilink fragment, a Markdown link URL, a bare URL or `<autolink>`, inline `$math$`, an HTML comment, or a text property. A tag *is* counted inside a `%%comment%%` and inside inline HTML (`<span>#x</span>`), and `a < b #x` is a tag, not an HTML tag — Obsidian counts all three, so the app does. Canonical form: NFC, then `toLowerCase()`; `_` ≠ `-`. Display: majority casing per path segment; the app writes the display casing, a new tag as typed. Frontmatter: `tags:` as a YAML list is canonical; the legacy comma-separated string is read, and converted to a block sequence the first time the app adds a tag to that file — the Properties panel does the same conversion but does not split the string, leaving `- alpha, beta` as one entry from which Obsidian then counts only `alpha` (F2); `tag:` is neither read nor written — Obsidian ignores it (F3, confirmed on 1.13.7), and a vault that still has one is a Format Converter job, not the app's. Invalid entries are indexed as `invalid` with position, never silently dropped.

**Settled by the fixture corpus** (#112; `packages/core/fixtures/obsidian-corpus/README.md`, Obsidian 1.13.7 — each rule cites its row):

- `#tag/` is the tag `tag`; the trailing slash is dropped (T2b). `#a//b` is counted with a literal empty segment, `a` → `` → `b` (T2c). `#1984` is not a tag; `#y1984` is (T2a). `# text` at line start is a heading, and a bare `#` is nothing (T2d, T2e).
- `#ML/Probing` and `#ml/probing` are one tag; the Tags pane shows it lowercase (T1b, T1c). `émoji🙂` counts (T1d).
- A `tags:` list entry containing a space is dropped, not counted as anything (`machine learning` → nothing, F8); a text property holding `#a-tag` contributes no tag (F7).
- Excluded contexts as listed above (T3a–k, T4, T5, T5b). A `~~~` inside a backtick fence does not close it (T4b).
- A `^id` is a block id only at the end of its paragraph (B4, B5), which is what puts the `## Annotations` note in a paragraph of its own — § Vault layout for the shape, **Block ids** below for what Obsidian did with each placement.

**Link grammar** (`help.obsidian.md/links`): `[[target]]`, `[[target|alias]]`, `[[target#Heading]]`, `[[target#H1#H2]]`, `[[target#^blockid]]`, `[[#Heading]]`, `![[embed]]` with `|WxH` and `#page=N`; `[text](target.md)` and `[text](target.md#Heading)` with `%20` decoding. Block ids: Latin letters, digits, dashes. Invalid in a target: `# | ^ : %% [[ ]]`. Resolution: a target with `/` by vault-relative path — except that a target beginning `./` or `../` (how Obsidian writes a Markdown link under its *Relative path to file* setting, and how it reads a wikilink written that way too, L5h) is first joined to the linking file's folder and normalised, with surplus `../` above the vault root clamped as Obsidian clamps it (L5a–i, #203). Otherwise by basename, case-insensitive, unique → resolved; several → *ambiguous* (resolves to nothing; a Loose Ends row under Disconnected material naming the linking file and the candidates, with the path-qualified rewrite arriving with the Vault editor in beat 11 — § Loose Ends); none → *unresolved*. `#^id` matches a block id in that file, including one on a `###` heading line (B2 — ADR 0006 decision 2 holds). `#Heading` matches heading text case-insensitively with surrounding whitespace trimmed (`#heading`, `#HEADING`, `# Heading ` all reach `# Heading`, L4). Basename resolution is case-insensitive (`[[sleep AND consolidation]]` resolves, L3). An escaped pipe `[[Target\|shown]]` is an alias link that resolves and displays `shown` (L1k, L1l); the package reads its target as `Target`, without the backslash — Obsidian writes `\|` only because a `|` would end a table cell — which supersedes #117's "keep the backslash" wording. Two same-named notes at equal depth: Obsidian opens the first it indexed, alphabetically `a/` (L2a) — the app reports *ambiguous* instead, per the divergences below. `%20` in a Markdown link is decoded for a note path and left alone in a URL (L1i, L1j).

**Block ids:** every `^id` in the vault is indexed, app-written or not. The app never rewrites or moves a user's. The per-Source `h` counter starts above the highest `^h<digits>` present. Obsidian's generated ids are six lowercase hex characters (`^6ea9c9`), placed at the end of the line on a paragraph or list item and on their **own line after a blank line** following a table or a callout (B1a–e) — the locator must attach such a trailing `^id` line to the block above it. Hand-written ids (`^h12`, `^c3`, `^my-own-id`) resolve like generated ones (B3). A `^id` names a block only when it ends that block's **paragraph**, which the locator's rule above already said and the corpus now confirms against Obsidian itself (B4, #164): on a two-line list item an id at the end of the first line names nothing, because the indented second line continues the same paragraph — end that paragraph with a blank line or a nested item and the same id resolves. Where the note is a nested item Obsidian's block is that first line alone and the locator's is the whole item (B4b), a divergence nothing depends on, the settled shape being B4c. A link to a `#^id` the file lacks is *not* drawn as unresolved (B4f), the same leniency L5f found for a missing heading, so the hover popover — *Unable to find "^id" in …* — is the only place Obsidian says so, and link colour is no oracle for a block id.

**What Obsidian itself does to a file** (F4, F5, S2–S5) — the app's preservation rules are stricter than Obsidian's own, and "as Obsidian does" is not their justification:

- The Properties panel rewrites the whole frontmatter block on any edit: `#` comments and blank lines are dropped, single and double quotes on untouched scalars are removed, a 4-space list re-indents to 2. Key order survives. A wikilink typed into a text property is written double-quoted (`related: "[[Sleep and consolidation]]"`, F5); dates are `YYYY-MM-DD`, date-times `YYYY-MM-DDTHH:MM:SS` (F6).
- An edit in Obsidian converts CRLF to LF (S3), strips a BOM (S4b), and leaves a missing trailing newline missing (S5). A BOM before `---` still counts as frontmatter (S4a); a blank line before it does not — the `---` is body (S2). Consequence for tests: `shape-crlf.md` in the corpus is an LF file because Obsidian touched it; the CRLF round-trip test (#56) uses a synthetic fixture Obsidian never edited.

**Divergences from Obsidian, by design:** display casing (majority per segment, not the pane's lowercase); ambiguous links resolve to nothing rather than to the first indexed; invalid tags are recorded rather than ignored; a write preserves CRLF, a BOM, comments, and quoting where an Obsidian edit normalises them away.

## Watcher and Ingest

The shape ADR 0013 decided, in enough detail to write against.

**Pipeline.** An event names a path; the event kind is ignored. The path is *stat*ted and compared to the recorded `{ size, mtime, hash }` — the sidecar's `file` for a PDF, the files table in `index.sqlite` for Markdown. Same size and mtime → nothing. Otherwise the file is hashed once it has *settled* — no events for the settle window, and two stats agreeing — and a hash equal to the last-ingested or last-written one records the new stat and stops: the app's own write, an iCloud re-download, a touch. A different hash is a change. PDFs that settle within one run window form one batch — one Ingest run, one `ingestLanded` event with the summary line. **Markdown batches close at settle:** a batch is everything settled by the time nothing else is pending — or, while something is still being written, by the time the batch's oldest settled path has waited one more window (#189: a rename is two events, and they must ride together whatever the platform's delivery) — as one index transaction, with no run window, so an Obsidian save reaches the Inbox in about the settle window rather than settle plus run window; the run window exists to make the iPad return one notification, and the index sends none (beat 1b). A file whose `blocks === 0 && size > 0` is *evicted*: unreadable-not-changed, never hashed; the Reader's read materialises it, and the events that follow no-op through the hash.

**Sweeps.** A stat-only pass comparing every file to its record, feeding the same pipeline: the whole vault at open and after a watcher error or overflow; `sources/pdf/` only when the window regains focus. Never a timer.

**Renames.** Within one batch, a vanished path and an appeared path with equal hashes are one rename. Every file is paired (the comparison is the same whatever the Kind, and a non-Markdown file is hashed for exactly this — #189); what a pairing *does* differs: a Note rename re-keys its dismissals; a PDF rename sets the Source's `pdf:` with `setFrontmatter`; an app-owned Kind needs nothing beyond the re-parse, since it is keyed by `id:`. Every pairing is reported as `renamed` on the event (below) so a surface can follow a file it has selected or open. Vanished alone → removed from the index (a PDF: the *missing* row below); appeared alone → new (a PDF: the *no Source* row below, or a *conflict copy*).

**PDF folder rows,** each a Loose end with one-click resolutions:

| Case | Group | Resolutions |
| --- | --- | --- |
| A new PDF whose document fingerprint matches an existing Source | Broken plumbing — *conflict copy* | *use this copy* (replaces the canonical file; the next Ingest re-matches every identity through the tiers) · *discard* (Trash) |
| A PDF no `pdf:` names | Unfinished reading — *no Source* | *attach to a stub* · *create a Source* — until then neither ingested nor indexed |
| A Source whose `pdf:` names a file that is gone | Broken plumbing — *PDF missing* | *locate* (fingerprint must match, else refused) · *detach* (clears `pdf:`; `## Annotations` and the sidecar stay frozen, every `[[citekey#^h<n>]]` keeps resolving) |

**`Q:` on every Ingest.** Evaluated against each annotation's current note. Spawns a Question once — the sidecar's `question` field — never a second; a later edit to the note does not rewrite the Question; removing the prefix does nothing.

**External Position edits.** When the index sees a Position's text change in a file the app did not write, a *pending Revision* — the previous text from the index before the change, the timestamp of the change — is recorded in `queue.sqlite` at once, and spliced into `## Position history` with `prependEntry` when the file has been quiet for 30 minutes, or on the app's next write to that file, or at vault close, whichever first. The row is written from inside the index chunk's transaction but into the other database, so the two commits are not one — a chunk that rolled back would leave a row the next read of the file diffs again, which the window's re-stamp rule below folds back into one entry; the error the two databases can disagree by is a duplicate entry, never a lost one. What #217 settles further: the diff is the sweep-and-batch path's alone (`own()` records the app's own Revisions itself, so an own write never raises a pending one), and only a field the file held *before* and still holds counts — a `## Working answer` heading retyped drops its row and brings it back, and reading that as a change would put two Revisions in the history for one typo. A second external edit to the same field inside the window re-stamps the parked row and keeps its `from`, the same rule a page save coalesces by (ADR 0020 decision 2); a page save made while one is parked opens a new entry rather than re-stamping the head, since the external edit stands between them. The splice runs through the page writes' own queue (`writeOwn`, `page-write.ts`), whichever Kind the file is, and the entries it carries go ahead of whatever else that write records, so the history stays newest-first. The window is the one number — the same injected `coalesceMs` the page's saves use. **Each of the three clauses has to be wired to something that fires it, and two were not** (#276, found by the beat-2 demo run): the quiet timer is now armed by `openPendingRevisions` for every row it finds already in the table, not only by `record`, so a Revision parked by a previous session is owed a splice from the moment the vault is open rather than from the next edit to its file; and *vault close* now includes the app quitting, which only the shell can see and so has to ask for (§ Decided). Until then the app's next write to that page was the only clause left, and a page the user never opened again showed its new answer with nothing saying it had moved — the silent shift story 40 exists to prevent, with the Revision safe in `queue.sqlite` and no trigger left to write it. A splice fired by a timer has no caller to reject to, so one that cannot land — a page that went while the app was closed, a vault on a volume that has — leaves its rows parked, owed again, and says so in the core's log.

**Ingest runs** are rows in `queue.sqlite`: started, finished, the four counts, per-file outcome, the Unmatched identities raised. Loose Ends reads the sidecar, never a run.

**Event stream** — `events.subscribe`, one per renderer, a discriminated union on `type`:

```
ingestLanded    { runId, summary: { new, questions, removed, unmatched }, sources[] }
vaultChanged    { changed[], removed[], renamed[{ from, to }] }   raised after the index commit; the renderer
                                   invalidates queries and applies `renamed` to any path it holds (a selection,
                                   an open file); it never patches list state
vaultStatus     { }                indexing progress or watcher state changed; the renderer re-reads `vault.status`
vaultSwitched   { vault }          today the window still reloads; a slice may stop that
scoutFinished   { scoutId, runId }   every run, failed or not; the run row carries the outcome
```

On every connect and reconnect the renderer invalidates *all* queries: the stream carries nothing replayable, and the invalidation is the catch-up for whatever was missed while it was down. Client: `httpSubscriptionLink` with the `eventsource` package (v5, fetch-based) as the ponyfill, the bearer header set on its `fetch`, behind a `splitLink` on `op.type === "subscription"` — shipped by #188 (`packages/renderer/src/trpc.ts`, `events.ts`). The core's bus (`packages/core/src/events.ts`) registers a subscriber when `events.subscribe` is called, not when the SSE producer first pulls, so nothing raised in between is lost. A vault switch still reloads the window; `vaultSwitched` is declared and not yet raised.

## Index

The shape ADR 0014 decided, in enough detail to write against.

**Engine:** `node:sqlite` (`DatabaseSync`), verified on the Electron the shell pins (44 → Node 24.21) with FTS5 compiled in; no dependency, no native module. WAL journal mode. `PRAGMA user_version` holds the schema number, a constant in the index module and independent of `vault.json`'s `schema`; a mismatch, a failed open, or a corruption error deletes `index.sqlite*` and rebuilds. On vault open the app writes `.vitrine/.gitignore` containing `index.sqlite*` if that file is absent.

**Tables,** one per outline concept, every row keyed by `path` (vault-relative). Keys named; beat 1b's tickets settle the rest of the columns.

```
files       path, size, mtime, hash, kind, id, display,          the watcher's stat record (ADR 0013 d.4). Every non-dot
            ldisplay, indexed_at                                 file has a row — a non-Markdown file carries its stat and
                                                                 hash too (#189: that is what pairs its rename) but no
                                                                 outline rows, and an evicted one its path alone until its bytes arrive; so `![[plot.png]]`
                                                                 and `[[paper.pdf]]` resolve
problems    path, channel, kind, problem, block                  channel ∈ unreadable | partial | shape; kind the file's
                                                                 Kind and problem, block as § Markdown's shape problem
                                                                 (#119). Written in the same transaction as the file's
                                                                 other rows, read by every surface's footer channel and,
                                                                 later, Loose Ends counts
fields      path, key, value                                     the frontmatter keys the app reads per Kind
headings    path, level, text, start, end                        section ranges, for owned-section checks and #Heading resolution
blocks      path, id, start, end                                 every ^id, app-written or not
links       path, target, heading, block, alias, embed, start,   resolution ∈ resolved | ambiguous | unresolved, resolved_path;
            resolution, resolved_path                            a derived column, recomputed by query (below; #191)
tags        path, canonical, written, source, start              source ∈ frontmatter | inline; invalid entries as `invalid`
fields_inline path, block, key, value                            outcome:: / relationship:: under a ### … ^c<n>
positions   path, field, text, hash                              filled by the Kind's positionsOf(outline, content), not the outline
frontmatter path, start, end, content_start, content_end, value  the whole parsed frontmatter as JSON, so vault.outline can be
                                                                 assembled from the index (#191)
list_items  path, start, end                                     every list item's range, likewise
```
`files.kind` is null for a plain Note and for a non-Markdown file. The `positionsOf` seam shipped with beat 1b with no Kind registered; beat 2 (#209) registers the Research Question with its one Position, `working answer` — the body of `## Working answer`, trimmed of the blank lines the app keeps around a section body, and no row at all when the heading is not in the file, so a heading retyped and restored never reads as the answer having been cleared — and the schema number moved to 3 so an existing index rebuilds with the rows; beat 2b (#301) moved it to 4 for the two Display name columns, which is the migration path for a denormalised column and the only one there is. Pending Revisions, `queue.sqlite`, and the splice land with the mechanism they belong to. What beat 1b pinned is that the seam is called for every changed file; the registry is composed in `app.ts`, and a test's stand-in adds to it rather than replacing it.
Not stored: body text, section bodies. Nothing from a sidecar or a PDF: the Source note's `## Annotations` blocks are outlined like any other block id, so `[[citekey#^h12]]` resolves through `blocks` and `links`.

**Refresh.** One transaction per watcher batch — or per **chunk** of one: a batch larger than 250 files (code) commits in chunks of that size, each raising `vaultChanged`, with link resolution recomputed per chunk over the basenames the chunk touched; the locator and `node:sqlite` are both synchronous, and 500 files settling together after a sync client reconnects must not stall the HTTP server. Outlining runs in-process; a worker thread only if measurement says so. Per path: for each changed path, re-outline, `DELETE … WHERE path = ?` across every table, re-insert; a vanished path deletes its rows. **The app's own writes are indexed by the write path**, synchronously, before the RPC returns: § Markdown's write already holds the content and the new hash, so it runs the same indexer in one transaction and records `{ size, mtime, hash }` in `files` — which is what makes the watcher's own-write no-op (ADR 0013 d.4) correct and keeps ADR 0010's landing instantaneous. The index module is therefore the one writer, fed from three places — the open-time sweep, the watcher's settled batches, and the app's own writes (ADR 0014, update 2026-09-20). Then recompute `links.resolution` for every link whose target basename or path the batch created, renamed, or removed — a query over `files`, not a re-outline of the linking files. A settled watcher Batch goes through `refresh(paths)`: the same stat comparison over its paths alone — a path that is a folder stands for everything at or under it, since Finder's delete and a drag in or out are one event for the folder — then the same chunked apply, so the sweep and a batch cannot disagree about what a change is; the sweep and every batch write one after another, never interleaved. The vanished paths ride in the first chunk's transaction and event, so a delete-plus-create that settled together is one `vaultChanged`. A path whose stat or hash matches its row is named in no event — an own write, a touch, and a byte-identical sync rewrite raise nothing (#188). Within one chunk a hash that left one path and arrived at another is a rename (#189, § Watcher and Ingest's rule): the rows are moved to the new path with `UPDATE … SET path` rather than dropped and re-outlined, and the pair is `renamed` on the event, in neither `changed` nor `removed`; a path whose content changed in place counts as having lost its old hash, which is how two files swapped in one batch each find their new path. `vaultChanged { paths }` is raised after the commit, by the code that committed it; `ingestLanded` likewise after the `## Annotations` rewrite's rows are in. At open: watch, then sweep (ADR 0013 d.3) — the sweep compares stats to `files` and re-outlines only the differing paths; a missing or mismatched database is a full rebuild through the same path, chunked like any large batch, so rows appear as it goes. Indexing never blocks the window: the app opens at once. Deleting `index.sqlite` while the app runs changes nothing visible — the open handle keeps the unlinked inode, and the next open finds no file and rebuilds; the watcher drops dot-entries, so the deletion is not observed and is not meant to be.

**Status.** `vault.status()` → `{ indexing: { done, total } | null, watching: { ok: true } | { ok: false, reason }, current: { ok: true } | { ok: false, reason } }`, invalidated by `vaultStatus`; `vault.rewatch()` reopens the watcher and sweeps. `current` is the `current()` predicate below, exposed here rather than as a module-only export so that beat 1b can pin it and beat 5's Ingest reads it from the same place (spec #177; the one divergence #185 records). The Inbox renders it in the footer channel where its `unreadable` count lives, and every later surface does the same, in prototype 12's words: `◐ reading the vault · 1,250 of 4,000 files` while a build runs; `‖ not watching — <reason> · retry` while the watcher is down for good (the reopen failed, or it never came up in the first place), glyph and label in `--color-warning` and on `role="status"` (ADR 0033); nothing when all is well. Never a banner or a modal. The same status decides a short surface's first slot (ADR 0032): only `indexing: null` with a live watcher may *claim* — warranted `read in full · watching`; a build running is *not yet*; a watcher down is *wrong*. A broken watcher must never look like a quiet vault (`CLAUDE.md` § Invariants).

**Watcher health** (#190). The watcher module's contract is that `watchVault` rejects when the watch cannot be proved live (the probe could not be written, or gave no event within its timeout), and that a live watch reports its death once — FSEvents' `error` (overflow included) — after closing itself; a settled batch the index could not apply is reported to the core's log and is not a death (#188: the next batch or the next open's sweep sees the same files again). Health is the vault service's: on a death it reopens the watcher and sweeps; on the *reopened* watcher's death it stops and reports `watching: { ok: false, reason }` — one automatic reopen recovers a transient fault, and anything that kills two watches in a row is for the user to see and retry, never a reopen-and-sweep loop the footer would not show. `vault.rewatch()` starts the cycle again. A watch that cannot be opened at all — or one that comes up and is then never heard from, which is the same rejection from the service's side — does not refuse the vault: it opens *not watching* and is still swept, so what is on disk is read once. `vaultStatus` is raised on every watcher transition after open (failure, reopen done, retry done) and on every chunk of a sweep — at open the sweep's first event is the status, and a not-watching open is read with the renderer's first `vault.status` query; the sweep after a reopen is started before the transition is raised, so a reader woken by the event never sees the watcher back and the index current with the catch-up still to come. `current` folds the reasons in this order: a sweep not completed or failed, a settled batch not yet applied (the index's own), then `not watching: <reason>` or `the watcher is being reopened` (the vault service's). The seam for tests is `AppOptions.watch`, `fs.watch` or a wrapper of it that fails what it made, refuses to make one, or makes one that never delivers; `AppOptions.probeTimeoutMs` shortens the probe's 5 s bound so that last case can be exercised without waiting it out (#272). The production bound is unchanged.

**`queue.sqlite`** (#217, `packages/core/src/queue.ts` — the file, its version and its migrations; a table's behaviour is its own module's, `pending-revisions.ts` and `open-days.ts`) opens beside `index.sqlite` at vault open, under `.vitrine/`, and is the index's opposite in the one way that matters here: it holds what is *not* re-derivable — today the pending Revisions an edit made outside the app owes its file (§ Watcher and Ingest, External Position edits) and the dates the vault was open (§ Loose Ends, #243), later the Ingest runs and the Scout tables — so it carries its own `PRAGMA user_version`, independent of the index's, and is **never deleted**. A version this build does not know is a migration it has yet to be given, so the vault is refused with `writeFailed` naming the file rather than opened without the mechanism; a version *behind* this build is migrated in place, one transaction per step, so a migration that fails leaves the database at the last version it reached; a `queue.sqlite` whose rows a newer Vitrine wrote is left exactly as it was. Deleting `index.sqlite` and rebuilding leaves the queue untouched, which is the point: the previous text a pending Revision holds is gone from the file the moment Obsidian saved over it, and no sweep could find it again.

**Unwritable `.vitrine/`.** A vault whose `.vitrine/` cannot be created or written (read-only volume, permissions) is refused by `vault.open` with `writeFailed` and the reason. It could not hold a captured Question either; there is no read-only mode.

**Columns** (#185, settling what the table list above leaves open): `files` also carries `markdown` (0 for a non-Markdown file, whose outline columns are null; its `size, mtime, hash` are recorded like a Markdown file's since #189, none of the three while it is evicted) and the file's `bom`, `eol`, `trailing_newline` choices, so `vault.outline`'s `file` can be assembled from the index, plus (#191) the lowercase lookup forms a link target is matched against — `lpath` (the path), `lname` (the basename), `lstem` (the basename without `.md`) — refreshed when a rename moves the row; plus (#301) the Display name (`CONTEXT.md`) the Global command matches on, `display` as the row shows it and `ldisplay` as it is compared — lower case, a run of punctuation replaced by one space and an apostrophe by nothing, so *slow-wave* is found by either half as well as the whole and *sleep's* stays one word; a lookup key like `ltarget` rather than merely the lowercased name, and both sides of every comparison pass through it, which is what lets the contains-`LIKE` carry no `ESCAPE`. Denormalised onto `files` so a keystroke matches a column here rather than scanning `fields`; no index on it, since SQLite cannot use one for a contains-`LIKE` (ADR 0027 d.5). `packages/core/src/display-name.ts` is the one place either is computed: the frontmatter key the Kind declares it in (`question:` on a Question and a Research Question, `title:` on a Source and a stub), or the Position it declares it in (`claim` on a Hypothesis, #340, whitespace runs folded to one space — the one Kind whose name is revised in its body), and the stored name for every other file and wherever that key or Position is missing or blank — a Partial Question is still reachable, and the Inbox is where it is reported as Partial. The Positions are computed before the `files` row is written so the name can be read from them, and schema 6 is what rebuilds an index holding a Hypothesis under its file name. A rename recomputes both from the rows already there, Positions included, so a moved Note is called what it is now called and a moved Hypothesis is still called by its claim; `fields.value` is JSON, so a numeric `page` survives; `headings` carries the heading line's `start, end`, the section body's `body_start, body_end`, and the `block` id on the line; `blocks` carries `marker_start, marker_end` beside the block's range; `links` carries `syntax`, `heading` (a JSON array), `block`, `alias`, `embed`, `ltarget` (the target lowercased, what the recompute selects by), `resolution`, and `resolved_path`; `tags` records an invalid entry with `canonical` null and the reason in `invalid`; `fields_inline` carries the line's range and the value's. A `problems` row's `problem` is the unreadable reason, the text `question or captured is missing` for a Partial Question, or the shape problem's name. Every row an own write or a sweep chunk produces goes in one transaction with `DELETE … WHERE path = ?` across all eleven tables first; a byte-identical rewrite (same hash, new stat) updates `files.size, mtime` alone. A folder the sweep could not list is an `unreadable` problem row keyed by the folder's path, with no `files` row; each sweep replaces those. The index module is `packages/core/src/vault-index.ts`; its seams — chunk size, the `positionsOf` registry, and the after-commit `onChanged` / `onStatus` listeners the event stream (#188) and the test harness hang off — are constructor options passed through `AppOptions.index`.

**Reads.** Every list a surface shows is a query here — Inbox rows, `vault.tags`, backlinks, Loose Ends counts, Coverage — and so is `vault.outline(path)`: the rows for that path assembled into the outline shape, resolution the same derived column every other surface sees, never a fresh outline of the file (which could disagree with `vault.tags` about the same file). A path the index has not reached yet returns what it has; `vault.status` says why. A `kind:` the app does not know is stored verbatim in `files.kind` with no problem row. A file's body is read from disk to display or edit it. **A write is never based on the index:** § Markdown's protocol re-reads and re-hashes the file for `basedOn`. **The one page read** (`researchQuestions.page`, `packages/core/src/research-question.ts`, #209) is the exception that proves the rule: the body is read from disk — it is what the page shows and will edit, and its hash is what the page's writes are `basedOn` — and the structure is outlined from those same bytes, so a section's range and its text can never come from two versions of the file; the index supplies only what one file cannot know, where each link lands, through `index.resolve(linkingPath, link)`, the same `resolveOne` the `links` column is computed by. The six sections come back with their line grammars parsed (a source or related line as its link, the link's resolution, and its note; a thread with its ticked state; a line under a heading that is not in the grammar kept whole rather than dropped), and beside the file's shape problems the page reports its own two — `sectionMissing` for a heading the file lacks, `sectionDuplicated` for one it carries twice among the five Edited sections (a doubled `## Position history` is already `ownedSectionDuplicated`) — which the index never stores, since a missing section is not a fault of the Kind (ADR 0008 decision 10), only something the page must say it could not show. Each link also carries the `files.kind` of the file it lands on (`resolvedKind`), which is what lets the page open a Question or Research Question by hash and leave a Note or Source inert until its surface exists; and the two Edited sections without a Position — `## Open threads`, `## Related questions` — come back with their body text as well as their reading, since a plain text field edits the text, not the parse (#221).

**Destinations** (#301, `packages/core/src/destinations.ts`): `globalCommand.destinations({ query })` → `{ rows: [{ kind, path, display }], total }`, the objects the Global command can go to — the Kinds with an Address, today `research-question` and `question`. Matched on `ldisplay` with a contains-`LIKE`, then ranked in the core by the prototype's four rungs (exact 3, prefix 2, word start 1, contains 0, both sides `matchKey`ed; an empty query is every object at one rung, which is what leaves the pre-typing list to Kind and recency), then by Kind in that same order, then by `files.mtime` newest first — never by a Question's `captured`, which is the Inbox's sort (ADR 0027 d.6). Capped at 50 with the true total beside it, as the Picker's is. No file is read, and nothing here knows about a Surface, a Dashboard or a hash: the renderer merges its own fixed set into these rows and does the final ordering across both. Shaped like the Picker's answer and deliberately not built from it (ADR 0027 d.3); the Picker keeps matching the stored name.

**Resolution** (#191, `packages/core/src/vault-index.ts`): recomputed inside each chunk's transaction for every link the chunk's files contain and every link whose `ltarget` is a lookup form of a path the chunk created, changed, removed, or renamed (both ends of a #189 pairing: the old name loses its links, the moved file's own `[[#Heading]]` follows it) — a query over `files`, `headings`, and `blocks`, never a re-outline of the linking files, which is what keeps a rename in a large vault cheap and is pinned by the ambiguity test (a `positionsOf` stand-in that never sees the linking file again). The rules § Markdown's link grammar leaves open, settled here: a target with a slash matches `lpath` or `lpath` + `.md`, case-insensitively like a basename; `[[#Heading]]` is into the linking file; a fragment the target lacks — a heading not there, a block id not there, `#H1#H2` with H2 outside H1's section — is *unresolved*, since the link points at something that is not there and that is what Loose Ends wants to hear; a fragment on a non-Markdown target (`#page=3` on a PDF) is a viewer hint and is not checked; `resolved_path` is filled only when `resolution` is *resolved*. `VaultIndex.resolve` — the one-link form a surface asks for a file the index may not have caught up with — answers with the files the *name* reached beside the verdict (#219): the two an ambiguous name is caught between, or the one an *unresolved* fragment landed on, so a surface can say *this file has no `^h99`* rather than *nothing carries this name* about a citekey that is right. The `links` table stores the verdict alone; the names are computed per call. A first build resolves each chunk against what the index holds so far and the later chunk that creates a target corrects the earlier links through the same recompute.

**`vault.outline` from the index** (#191, `packages/core/src/vault-outline.ts`): the same input errors as before (`outsideVault`, `notMarkdown`, through the same locator), then the rows for the path — `frontmatter`, `headings`, `blocks`, `links` with `resolution` and `resolvedPath`, `tags`, `fields_inline`, `list_items` — in insertion order, which is document order, with criteria and shape re-derived from those rows by the same `deriveKind` a fresh outline uses, so the two cannot disagree. No `files` row → `{ readable: false, reason: "not in the index" }`, the reason naming `current`'s reason while a build runs; a Markdown row with no file choices was never outlined and answers its `unreadable` problem row.

**`vault.tags`** (#191, `packages/core/src/vault-tags.ts`): `{ tags: TagNode[], invalid: [{ path, written, reason, source }] }` where a node is `{ canonical, display, name, implicit, count: { inclusive, exclusive }, files, occurrences: [{ path, written, source }], children }` — roots are first segments and siblings sort by canonical form; counts are occurrences, exclusive of this tag exactly and inclusive with every descendant; `files` is the inclusive union; an implicit node has no occurrence of its own; `name` is this segment's majority written form across every occurrence at or under the node and `display` the full path so cased (T1c's `ml/probing`, with a tie going to the canonical form if it was written, else the form that sorts first, so file order never decides); the empty segment of `#a//b` is a node named `""` under `a` (T2c). Paths are vault-relative.

**`vault.kinds`** (#347, `packages/core/src/vault-kinds.ts`): every `kind:` the vault holds at least one file of, sorted — `SELECT DISTINCT` over `files.kind`, so a file with no `kind:` contributes nothing and one the app does not know contributes its Kind verbatim. A presence test, not a count: its one reader is the Sidebar, which draws a built surface's entry hollow, with where its contents come from, only while this answers without the Kind *and* the vault is read in full and watched (ADR 0032 — saying an entry is empty is a claim). Re-read on every `vaultChanged`, like every list.

**Inbox under external change.** `vaultChanged` invalidates `questions.list`. The selection stays keyed by path (ADR 0010): a selected file that is `removed` clears the selection, focus untouched, nothing announced — the row's absence is the message; a selected file in `renamed` has its selection moved to `to` before the re-query lands, so a Question renamed in Obsidian stays selected. No dependence on `id`.

**`current()`.** True when the open-time sweep has completed, the watcher has no unrecovered error or overflow, and every Markdown batch that settled before the caller's Ingest run started has been applied; otherwise false with the reason. Ingest flushes pending Markdown batches, then asks; a file still inside its settle window is not waited for. Tier 5 (§ Annotation identity) concludes *removed* only when this is true.

**Full-text search** joins with the Vault surface as an FTS5 virtual table over body text — additive, no existing table changes. The index is where search lives; no separate search library.

## Vault surface

The shape ADR 0015 decided, in enough detail to write against. Everything here is cheap to change; the ADR holds what is not.

**Editor.** `@codemirror/state`, `@codemirror/view`, `@codemirror/language`, `@codemirror/lang-markdown` (`@lezer/markdown` underneath). One React component owns one `EditorView`: created in an effect, destroyed on unmount, the file's text pushed in with a single whole-document `dispatch` only when the *file* changes, a `dirty` flag kept from `updateListener`'s `docChanged`, and `state.sliceDoc()` read at save time. React never re-renders per keystroke. `@uiw/react-codemirror` is not a dependency.

**Two parsers, one grammar.** The editor's structure comes from `@lezer/markdown` (CommonMark + GFM, incremental: 0.75 ms per keystroke at 200 KB, measured in #133) extended with four `InlineParser`s — tag, wikilink, block id, `key:: value` — whose recognition and canonicalisation are calls into `packages/markdown`'s exported grammar functions; the Lezer parser supplies the context (not inside a code span or link destination) that ADR 0008 decision 4 bought micromark for. The micromark outline stays the truth for everything the core does. The fixture corpus (#112) gains a parity check: both parsers find the same tags and links at the same offsets on every fixture. Outline-driven decorations (re-run the locator on every `docChanged`, 200 ms at 200 KB, not incremental) are the fallback if the parsers drift and cannot be kept in step.

**Offsets and EOL.** CM6 counts every line break as one position regardless of separator; a CRLF file's outline offsets computed on the raw string do not equal editor positions. Decorations are computed on `state.doc.toString()` (LF-joined), never on the file bytes. The file's EOL (the read already knows it) is set as `EditorState.lineSeparator` so the save round-trips it; BOM and trailing newline are stripped before the editor and re-added by the write (§ Markdown, file-level rules). A CRLF fixture is a required test.

**Live preview, inline only.** Off the cursor's line: `**`, `_`, backticks, `[[`/`]]` and the alias pipe, `#` heading marks, and `^blockid` are hidden (`Decoration.replace`, `atomicRanges` so a hidden `[[` cannot be half-deleted); wikilinks and tags render as links, click follows them. All of it is a `ViewPlugin` over `visibleRanges`. Frontmatter, embeds, tables, and callouts are shown as text — Obsidian's source mode — and each block widget (a Properties block first) is its own later slice, added one at a time, in a `StateField` mapped through `tr.changes`.

**Theme.** A `HighlightStyle` mapping Lezer tags to classes, styled from a CSS Module scoped to the editor root with semantic tokens only; the brand lint rule covers it. Prose in the body face, code spans in IBM Plex Mono, questions and quotations in Source Serif 4 as the prototype draws them.

**Save.** Autosave on a short idle (Obsidian's ~2 s), and on blur, file switch, and window close; `⌘S` saves now. Every save is `replaceFile(content, basedOn)`, `basedOn` the hash of the text last read from or written to disk; the watcher no-ops on the app's own hash (§ Watcher and Ingest). The handler diffs Positions (`positionsOf`, § Index) between that text and the new content and records Revisions at once with `prependEntry`, coalescing within ADR 0006's 30 minutes; it never verifies shape (ADR 0015 decision 4).

**Changed on disk.** `vaultChanged` naming the open path while the editor is dirty, or a hash-mismatch refusal from `replaceFile`, shows the line inside the editor pane with the file's mtime relative: *keep mine* re-reads the hash and saves; *take the disk copy* replaces the document and clears `dirty`. Autosave is suspended while the line shows. A clean editor reloads silently on `vaultChanged`, preserving scroll and cursor where the text allows.

**Panes.** Three, inside the surface slot the Sidebar already frames: a left pane tabbed *files* / *tags* (search joins when full-text search does), the editor, and a right pane for backlinks. The Vault surface accepts a vault-relative path to open, so a `[[link]]` on any other surface lands here.

- *Files*: the vault tree with a Kind glyph per file (◆ question · ● source · ○ stub, the Inbox's family), Source rows showing their annotation count, `.vitrine/` hidden. Read-only in the first slice — no rename, move, delete, or new folder; *new note* is one command writing to `notes/`. Stub and Source rows expose the Reader beat's *attach a PDF* and *open in reader* commands.
- *Tags*: the tree from `vault.tags`, inclusive count (with children) and exclusive count (this level only) per node; clicking a node lists its files. No rename, no drag: tag hierarchy management is out of scope by the brief (`#### Tags as topics`), whatever the prototype's caption says.
- *Backlinks*: linked backlinks only, from `index.sqlite`'s `links` table, each with the linking file's Kind glyph, a context snippet read from that file's body, and its Kind · field · date line. When the open file is a Source, rows group by the `^h<n>` block they target — the annotation-level backlinks Prompt 7 asks for — with file-level links listed beneath. *Unlinked mentions* wait for full-text search.

**First slice.** Tree, editor, backlinks, tag browser, changed-on-disk, autosave. Later slices of the same beat: full-text search (FTS5 in `index.sqlite`, ADR 0014 decision 12) with the *search* tab and unlinked mentions; block widgets starting with a Properties block; folder operations; the graph view (fog on map #131; never force-directed, ADR 0015 update of 2026-09-26).

## Settings

The shape ADR 0025 decided, in enough detail to write against. Three sections, in this order, each one a statement about how this vault is arranged; nothing here is a preference (ADR 0025 decision 2). Address `#/settings`, opened by ⌘, and by whatever the Sidebar draws; unreachable while First run is on screen.

**Where the vault is.** The open vault's path, *reveal in Finder*, the App state folder (`<vault>/.vitrine`, *the one folder the app keeps for itself* — prototype 13's row, reworded because the app also writes Artifacts into the vault, ADR 0035), and whether the watcher is healthy and since when — answered by `vault.current` and `vault.status` (§ Index), whose `watching` carries `since`, the time the live watch came up: at open, or at the reopen after a failure, since what fell between was caught by a sweep rather than seen. *Reveal in Finder* is `vault.reveal`, which takes no path — the core reveals the open vault's folder, so the window cannot point Finder at anything else — and asks the shell over the process channel the chooser uses (`Host.reveal`, `shell.showItemInFolder`); a client with no host reveals nothing, as it picks nothing. No relaunch, nothing written on either side, and no recent-vaults list (ADR 0025 decision 7).

**Where the PDFs are.** Four facts and no control: the path (`<vault>/sources/pdf/`, § Vault layout), whether it resolves and *to what* — `realpath` of the entry, printed in full when it is a symlink — the number of PDFs in it and their total size, and the most recent arrival — its time and file name. The last arrival is remembered in `queue.sqlite` as the watcher sees it, so an entry that stops resolving still says when papers last came (*the last before it stopped resolving*) while *holds* reads *not known*. A fresh vault reads *`sources/pdf/` is an ordinary folder in your vault. Nothing has arrived yet.*, with one sentence saying a symlink to an iCloud or Dropbox folder is something the researcher makes in Finder, and *reveal in Finder*. An entry that does not resolve is a **fault**, drawn as one — the only genuinely broken thing this surface can show — never as an empty folder. It is sounded in the footer channel, where *Not watching* lives (*papers not arriving* — the reason names the fault, never the path, ADR 0028 — with *check again*, which runs the sweep), and only stated here; it is not a Loose Ends row, since the footer already raises it and a second place would drift from it. **There is no procedure that creates, repoints or removes that symlink, and none that copies a PDF into or out of the folder** (ADR 0025 decision 6): the absence is what makes "Vitrine never moves a byte" (§ Decided) a property of the API, as no `credentials.get` is for BYOK.

**What it talks to.** One block per Provider — today exactly one, *Anthropic* — over ADR 0017 decision 4's RPC, unchanged: `credentials.status | set | delete | test`, no `get`. Per block: the key's state (*no key stored* · *a key is stored* · *key rejected*), a key field that never echoes what is stored, the editable model id from `providers.json` (§ BYOK and watched sources), *test*, and *remove*. No *add a provider* control. Beneath it, the Scouts currently **blocked on credentials** on that Provider, **named and never counted** — each a link to its row, derived from the same run rows as Home, Loose Ends and Scout Activity (ADR 0016 decision 10), so the four cannot disagree. A locked Keychain or a denied ACL dialog is a fault shown as one, never folded into *no key*.

**Empty states.** Settings is never empty: each section has a true sentence for the case where the answer is nothing, and that is the reference the other surfaces' honest-empty treatment is drawn against rather than an exception to it (story KEEP-10, ADR 0025 decision 9).

**Beats.** Beat 4b ships the surface with its first two sections, before beat 5, because Ingest is the first thing that silently depends on the PDF arrangement; it does not wait for beat 4, which touches nothing here (grilled with beat 4, 2026-09-28). It adds no Loose Ends rows and no Home items. ## Scouts

The shape ADR 0016 decided, in enough detail to write against. Numbers are code, recorded here as starting points.

**arXiv client.** `http://export.arxiv.org/api/query`, one client shared by every Scout: requests are serialised on one connection with a **3 s** gap (the ToU), paged at `max_results=100`, sorted `submittedDate` ascending so a ceiling cuts the newest, not the oldest. A run's query is the Scout's Query wrapped as `(<query>) AND submittedDate:[<from> TO <to>]`, `from` = the previous run's `window_to` (creation time for the first run; the backstop for a Retroactive search), `to` = now, both GMT. **Ceiling: 500** items per run; a run that hits it records `truncated` and the Queue shows *stopped at 500 — N more matched* from `opensearch:totalResults`. A malformed query comes back as an Atom feed with one error entry; that is a `parse` failure, not an empty run. Atom fields → Proposal: `title`, `author/name[]`, `published` (first submission — the only date arXiv has), `arxiv:journal_ref` → venue when present, `summary` → abstract, `link rel=alternate` → url, `arxiv:doi` → doi, `id` → `arxiv_id` with the trailing `v<n>` stripped. Keywords: never; the card omits the row rather than showing it missing, since arXiv is known never to supply it (ADR 0018 d.9).

**Scheduler.** At vault open and every **hour** while open, every unpaused Scout whose `now − last completed run ≥ cadence` (daily | weekly | monthly) is queued on the client in creation order. *Run now* queues one regardless. A run that fails does not advance `window_to`; the next attempt re-covers the same window, and identity by `arxiv_id` makes the overlap harmless.

**Form.** Name, Query, cadence, Assigned Questions (a picker over open Questions), starting Lane, and *also search back to* (default backstop **90 days**, per Scout on creation). *Try* sends the Query once with no date window and shows `totalResults` and the first five titles; it writes nothing.

**`queue.sqlite`,** the Scout tables — additive to the Ingest-run and pending-Revision tables ADR 0013 put there:

```
scout_runs    id, scout_id, started, finished, outcome (ok | failed), error_kind (network | http | rate_limited | parse),
              error_message, window_from, window_to, retroactive, fetched, new, truncated
proposals     id, source_key (unique; ADR 0017), doi, title, authors (JSON), published, venue, abstract, url,
              lane (review | skim), state (pending | deferred | accepted | rejected), first_seen, stub_path
appearances   proposal_id, run_id, scout_id, seen_at, url
triage        proposal_id, action (accept | reject | defer | promote), at
```

Health per Scout is a query: last `ok` run, last run with `new > 0`, and the newest run's `outcome`/`error_kind`; *broken* = newest run `failed`. Accept rate (beat 9) is `accept` over `accept + reject` in `triage`, Review-lane rows only, bucketed by `at`.

**What that query renders** (ADR 0032). The same result yields a Voice and, for a Quiet field, a Warrant, so no surface composes its own. *Wrong* when the newest run `failed`, carrying **one sentence per `error_kind`**, written in the core and rendered verbatim by Home, Loose Ends and Scout Activity — the surfaces choose their actions and whether to show it, never the words. *Not yet* when the Scout has no runs, is `paused`, or is blocked on credentials, carrying the reason it has not looked and no Warrant. *Claim* otherwise, and when the last run with `new > 0` is older than the last `ok` run it is a Quiet field, whose three Warrant fragments are: the newest run's `finished`; that its `outcome` is `ok`; and the Scout's own rate of finding, `count(runs with new > 0)` over the window those runs span, phrased as *usually ~N a week* — `no baseline yet` until there are enough `ok` runs to divide, never an omitted fragment. Nothing here is stored: a Voice is as re-derivable as the health it reads, for the reason decision 10 gives. Accept rate is unavailable — stated as why, not as a number — while ≥ 50 % of the Scout's proposals in the window are missing `authors` or `venue`, since ranking reads those; that is a fact about the measure and never a health state.

**Queue reads.** Review: `state = pending`, grouped by Scout, newest `first_seen` first, one card in hand and the rest listed. Deferred rows return to `pending` when a run for that Scout finishes `ok`. Skim: `lane = skim`, lines older than **30 days** behind a *show older* line, nothing deleted. A Proposal with several Appearances shows each Scout on the card.

**Triage keys** (ADR 0016's update of 2026-09-26, #255) — `A` accept · `O` open · `P` pass, the grammar every machine proposal in the app shares, plus the Queue's own `R` reject and `D` defer. Only `A`, `R`, and `D` write a `triage` row; *open* and *pass* record nothing, so a Proposal the user looked at and left is indistinguishable from one never reached, which is what *pass without deciding* means. Beat 8's inferred-link review uses the same keys, `D` absent.

**Accept.** `createFile` of `sources/<citekey>.md` per § Vault layout — `citekey` minted from `authors`/`published` by the existing rule, `kind: source-stub`, `title`, `authors`, `year`, `doi` and `url` when present, `origin_scout`, `origin_question` (every Assigned Question), `origin_retroactive`, `appearances` (every Appearance's url); body: the abstract as `> ` quoted lines, written once. The row records `stub_path`; a stub whose file is later gone is a Loose end, not a re-accept.

**Loose Ends rows this beat adds** — *Broken plumbing*: a Scout whose newest run failed (error kind shown; *run now* · *pause* · *open*). *Unfinished reading*: `kind: source-stub` with no `pdf:`, oldest first, resolving through ADR 0013's *attach to a stub*. **Owed to Home (beat 12):** Review depth (pending Review rows), broken Scouts, and the one claim Home makes about the Scouts — *N watching, these are not* — named and never counted (ADR 0032 decision 8).

**RPC.** `credentials.status(provider) → present | absent`, `credentials.set(provider, key)`, `credentials.delete(provider)`, `credentials.test(provider)` (one minimal call; returns ok or the error kind). No `credentials.get`. The Credentials panel is a section of Settings (§ Settings, ADR 0025); the app-menu door is gone, and the Scout form's *Add a key* is a `pushRoute` to `#/settings` that the form's values must survive.

**Fetch.** One URL per Scout, one fetch per run. `User-Agent: Vitrine/<version> (+https://tacomancy.com/vitrine)`; `robots.txt` Disallow → `http` failure, message *disallowed by robots.txt*; timeout **30 s**; response cap **2 MB**; no retries within a run. Feed autodiscovery on every fetch (`<link rel="alternate">` with an RSS or Atom type); a feed's entries map to the card directly — `title`, `author[]`, `published`/`updated` → date, `summary`/`content` → abstract, `link` → url — and the model is not called.

**Reduce.** HTML → text with links (scripts, styles, `nav`/`header`/`footer` stripped, links kept as `[text](href)`), capped at **40K** input tokens (`count_tokens` before the call); a capped run records `truncated`. The run stores `page_hash` (SHA-256 of the reduced text) and `page_length`. `page_hash` equal to the last `ok` run's → `ok, new = 0`, no model call.

**Extract.** System prompt: the card fields, *copy, never compose — every value must appear on the page; null when it does not; no summaries*. Schema: `{ items: [{ title, authors: string[] | null, date, venue, keywords: string[] | null, abstract, url }] }`, every scalar `string | null`. **Verify:** an item is kept only if its `title` and `url` both occur literally in the reduced text; dropped items count as `unverified` on the run. Item url → `source_key`: `arxiv:<id>` when the url is an arXiv abs/pdf link (version stripped), else `doi:<doi>` when a DOI is present, else `url:<normalised>` (scheme+host lowercased, fragment dropped, trailing slash and tracking query keys removed).

**Outcomes.** `ok` when ≥ **50 %** of returned items verify and (items > 0 or the page did not change). `extraction` when < 50 % verify, or when zero items return while ≥ 50 % of the last `ok` run's verified titles still occur in the text (message *listing missed*), or when zero items return and they do not (message *structure change*). `credentials` when the store has no key or the provider answers 401 (message *no key* / *key rejected*). `model` on a provider error after retries, a `refusal` stop (category in the message), or a schema violation. `rate_limited` on 429 after retries. A Scout with a Watched source and no key does not run: health shows *blocked on credentials*, a state apart from *broken*.

**First run.** No date window; "new" is an unseen `source_key`. The first run's Proposals carry `origin_retroactive`; the form hides *also search back to* for a Watched source.

**`scout_runs` gains** `model, input_tokens, output_tokens, cache_read_tokens, cost_usd, page_hash, page_length, unverified`; `error_kind` gains `credentials | model | extraction`.

**Loose Ends rows this beat adds** — *Broken plumbing*: *blocked on credentials* (→ *open Settings*); *structure change detected* — an `extraction` run on a Scout with a prior `ok` run that found items (→ *open the page* · *run now* · *pause*). The failed-Scout row shows the new kinds. **Owed to Home:** a Scout blocked on credentials is one that is not looking, so it is named in Home's coverage claim beside a paused one — never added to the broken count, which counts failures (ADR 0032 decision 8; ADR 0025 decision 3's *named, never counted*).

## Lexicon

The shape ADR 0018 decided, in enough detail to write against. Numbers are code, recorded here as starting points; lands with beat 10.

**Phrases at refresh.** Body text is not stored in the Index (§ Index), so the Index's outline of a Source or Source stub also emits a per-file phrase table: every 1–3-word phrase from `title` and from the body's abstract (the `> ` quoted lines a stub is created with, or the same shape on a Source), lower-cased, ASCII-folded, punctuation-stripped, with a stopword list applied to phrase edges, and its count in that file. One more table, refreshed in the same transaction as the rest:

```
phrases     path, phrase, count                                  1–3-word phrases of a Source's title and abstract
```

**Tag's papers** is a query, never stored: files carrying the Tag in `tags`, plus Sources and stubs reached from a Question carrying it through `links` from its Related, a Research Question's supporting and opposing lists, or a stub's `origin_question` field — the same query Coverage uses. A parent's papers are the union of its descendants'.

**Derivation,** per Tag, whenever a refresh touched a paper of that Tag or its `tags` rows: candidates are phrases present in at least **2** of the Tag's papers (an Author keyword skips this floor); score = number of the Tag's papers containing the phrase × log(total papers in the vault ÷ papers in the vault containing the phrase); Author keywords get a fixed **×2** on that score; then Excluded Terms are dropped, Seeds are added at the top, and the top **K = 10** are the Lexicon, the remainder kept as *not used* for the editor. Author keywords come from the file's `keywords:` field and from the Source's sidecar (`annotations/<source-id>.json`), where a later slice records keywords read from the PDF at Ingest; no Ingest writes frontmatter.

**Unplaced:** fewer than **N = 3** of the Tag's papers have any phrase rows, and no Seed.

**Compilers,** one per Structured source, over the top-K Terms as an OR of quoted phrases: OpenAlex `filter=title_and_abstract.search:("t1" OR "t2" …)` for the growth-rate count, split and unioned client-side if the URL nears 4 KB; arXiv `(abs:"t1" OR ti:"t1" OR abs:"t2" …)` for a Scout whose Filter names the Tag, wrapped in the run's `submittedDate` window as § Scouts. The editor shows each compiled string verbatim.

**Measurements** (beat 10) store the compiled OpenAlex query on every row; a Tag whose current compiled query differs from its newest measurement's is *re-measure pending* until the next sync.

## Research Question view and triage

Beat 2 (map #131), grilled 2026-09-20; the ADR is 0020. Assumes `packages/markdown` (#117) and the watcher + index (1b) have landed: every list is an index query, every write is one of the seven operations, and this beat contributes `positionsOf` for the Research Question Kind (one Position: `working answer`, the body of `## Working answer`). Markdown-only: the Sources it can attach are whatever `kind: source | source-stub` files the vault already holds; annotation-level links wait for the Reader beat.

**Triage from the Inbox** ships four of the five actions — promote to Research Question, link, answer in place, drop; promote to Hypothesis arrives with beat 3, and no key is reserved for it. Each is one write through the protocol (the keys are in § Vault layout). A promotion lands on the new page (ADR 0010's rule: the surface the object landed in takes the keyboard). A write the protocol would not make, or a triage action the object's state does not allow, is the `refused` VaultError kind (#210); the row shows its message. Which Statuses each action allows: promote, answer and drop act on an *open* Question, reopen on an *answered* or *abandoned* one. A *promoted* Question is left to its page — answering or dropping it from the Inbox would leave the page open behind a Question that says it is finished, and the page's own *resolve* and *abandon* write back to both (#212). Promotion is `promoteQuestion` in `packages/core/src/research-question.ts`, serialised with captures by the questions service since both pick a free name in the Question's folder; the page is written first and whole, then the Question's two keys, and a mark the protocol refused takes the page back so no page exists that nothing points at.

**Editing on the page.** Each Edited section is a plain text field: autosave on blur, `⌘↵` saves now, `⌥↵` saves and opens the one-line why (Working answer only), `esc` reverts unsaved typing. The three are named under the Working answer's field while it has the keyboard, as the 03 prototype's editing panel names them — `⌥↵` is a gesture nothing else on the page would mention — and nowhere else, because a page being read does not need them. The field is opened by *edit* beside the section's label — the sections read as their parse (ticks, links) until asked to be text — and *edit* takes the keyboard back when the field closes. `## Open threads` and `## Related questions` are saved by `researchQuestions.saveSection` — `replaceSection` with the field's text, no Revision — and a thread's tick is `researchQuestions.tickThread`, which names the thread by its text rather than its position, rewrites the task marker on that line, and replaces the section whole, so a tick still lands where it was meant on a file edited underneath, or refuses when the thread is no longer there (#221). Both answer the write's own result; a refusal is a line inside the section that asked. A capture with the page on screen is `questions.capture` with `{ context: "pursuing", page: <the page's path> }`: the Question is written with `from: [[<name> (RQ)]]`, its link is appended under `## Related questions` in the same call, and a page that cannot take the line takes the Question back with it — whole or not at all, as with the vault marker. A save is `replaceSection` with `basedOn` the hash of the text the page was given and `was` that section's text as the page read it — a whole-file hash cannot say *which* section moved, and re-apply locates the section afresh and would replace it whole, so the field sends what it is editing against (#215). A section that no longer reads that way refuses with `changedAndUnreapplyable`; anything else the file did re-applies and lands. The refusal shows as the Vault editor's *Changed on disk* line inside that section — *keep mine* (the disk copy re-read, the typing saved over it) / *take the disk copy* (the field replaced with what is on disk) — with autosave suspended until chosen. Both are captured when the field goes dirty, not re-taken from a re-read underneath it, so a `vaultChanged` between opening the field and saving does not make the save look based on the new file. The page header derives "revision N of M · held <since latest>" from the entries. The history is the page's `## Position history` rendered in place, newest first, with two filters — *everything* and *explained only* — quiet Revisions collapsed into "N quiet revisions over <span>" with *+ why* on hover to explain one after the fact; "open full history" in the side column is a jump, not a route. *+ why* sits on each entry a trail opens on rather than on the trail itself: a run of four says how often the answer moved, and which of the four a why belongs to is not a summary's to guess.

**The why is a second write, never part of the save** (#216). `⌥↵` saves, and the save's reply names the Revision it recorded — an entry has no id, so its timestamp is the only name there is — and only then does the line open; `esc` on it leaves an entry that is already on disk unexplained, which is what makes escaping a decline rather than a cancel, and `↵` over an empty line is the same decline. Both the line and *+ why* call `explainRevision`, which replaces `## Position history` whole with that entry's `why:` line spliced in and every other byte of the section put back. An entry is named by its timestamp and its field — the timestamp alone stopped being enough with the Hypothesis, whose claim and design notes can be saved in the same second (#333) — and a pair no entry carries, or one two entries carry, refuses and says which, as a ticked thread does; so does a Revision that already carries a why, because this write replaces the entry whole and the why is a sentence somebody wrote. A why is one line: a newline in it is collapsed, as a source line's note is, or it would end the list item and leave its tail as prose. `[[` in the line opens the one picker narrowed to nothing, and the text it completes with is `wikilinkTo`'s (`picker.linkText`), not the bare name — the why is where the evidence for a change of mind lives, and a name two files answer to would send it to the wrong one.

**One picker.** Link (Inbox), attach a source, and `[[` inside a why line share one component over the index's `files` table: name-contains, Kind glyph per row, the caller narrows the Kinds (Link: Questions, Research Questions, Notes, Sources and stubs; attach: Sources and stubs; why: anything). The attach form asks for the side (required), a note on why it is here (optional), and can create a stub inline when nothing matches. Name search is enough for a picker; full-text search is beat 11's.

The query is `candidates` in `packages/core/src/picker.ts` behind `picker.candidates` (#211), and the component is `packages/renderer/src/Picker.tsx`. A row is `{ path, name, kind, title?, pdf? }`: `kind` is the file's `kind:` verbatim, or `note` for a Markdown file that declares none, and the glyph it carries is the renderer's (`kinds.ts`, extending § Vault's ◆ ● ○ with ■ for a Research Question and `·` for a Note). `title` and `pdf` are on Sources and stubs alone — the two paper Kinds. `title` is the file's `title:`, shown beside the citekey because `rasch2013` is the name the vault files a paper under rather than one anyone recognises it by; absent when the file carries none, never fallen back to the file name the row already shows. It is **shown, never matched**: the query is still name-contains, and matching a title or a body stays beat 11's. `pdf` is **derived** — the `pdf:` key naming a file the index holds under `sources/pdf/`, never the key on its own. Beside the Kinds, the caller passes the paths to leave out, so the picker never offers the file its opener is standing on. The rows come back capped at 50 with the total beside them, and the picker says *N of M — keep typing* rather than cutting the list silently.

**Attach a source** (#218) is `attachSource` in `packages/core/src/research-question.ts`, behind `researchQuestions.attachSource`: one `appendToSection` under `## Supporting sources` or `## Opposing sources`, writing `- [[citekey]] — why it is here` and the bare link when there is no why. The side is required and has no third value, so a call without one is an input error rather than a default; a note carrying a newline is collapsed onto the line, which would otherwise end the list item and leave its tail as prose. The target must be a `source` or `source-stub` the index knows — a side is where evidence goes, and a Question or a Note landing there would read as evidence ever after (ADR 0020 decision 5); a Note is the index's null `kind` column and is refused by that Kind, not mistaken for a file the index has no row for. The wikilink is written by the same shortest-reach rule Link uses, now `wikilinkTo` in `packages/core/src/link-text.ts`, shared by both writes. Unlike Link, attach does not refuse a source a side already holds: Link writes `related` whole and so must not repeat itself, where a side is a list of judgements — one paper can carry two findings, each with its own why, and which of two lines was meant is not the write's to decide. The form is `packages/renderer/src/AttachSource.tsx`, opened by `⌘⇧A` from any focus on the page and closing back onto the focus it took: the one picker narrowed to Sources and stubs, then the side, then the optional why. Above the two columns the **balance strip** states the counts in words — *4 supporting · 2 opposing*, *1 supporting · nothing opposing*, *nothing attached on either side* — and when exactly one side is empty it steps onto its own surface with a brass `!`, its label, and a sentence naming a one-sided literature as a property of the reading. A page with nothing on either side is new, not one-sided, and stays quiet.

**A stub made by hand** (#220; ADR 0020 decision 7) is `createSourceStub` in `packages/core/src/sources.ts`, behind `sources.createStub`: one `createFile` of `sources/<citekey>.md` with `kind: source-stub`, `citekey`, `title`, `authors`, `year` and `url` — the record a Scout's *accept* will write minus its Origin, with no `id:`, because the citekey already identifies a paper and the two paths must write the same record (ADR 0016 decision 9's list starts at `citekey`, as the vault's own stubs do) — and an empty body, because nobody typed an abstract. A field nobody filled in is absent rather than empty, and the title is the one the record cannot do without. `citekeyFor` is the rule alone and pure, so it reads off a table of cases: the first author's surname (the text before a comma when the name is written surname-first, the last word otherwise), ASCII-folded and lowercased, then the four-digit year; the first word of the title that survives folding when no author was typed, and `source` when nothing does. The authors field separates on `;` and not on `,`: a comma already means surname-first inside one name, and `Klinzing, J.` would otherwise split into two people. A citekey already on disk takes the next suffix — `a`, `b`, … `z`, `aa` — rather than refusing: two papers by one author in one year is ordinary, and the collision is the rule's own case, not an error for the user to solve. The check is `createFile`'s own refusal, so a file the index has never seen still counts as taken. Stubs are made one at a time, in a queue `createSourceStub` holds itself rather than one the caller must remember, for the same reason Link holds one: picking a free citekey means reading the disk and then writing to it. The index is told of the write before the call returns, so the form attaches the new paper in the same breath. In the renderer it is the attach form's third face (`AttachSource.tsx`), reached from the picker's no-match state — where `↵` takes *new stub* because there is no row to take — and leading into the side step, which no path skips: making the paper is not the judgement that it is evidence.

**Link** (#211) is `linkQuestion` in `packages/core/src/link.ts`, behind `questions.link`: one `setFrontmatter` writing `related` whole, with the entries the file already holds kept and the chosen file appended. The linking side only — the backlink is the index's (`CONTEXT.md` *Related*). The wikilink written is the bare name when the index says that name reaches this file and nothing else, and the vault-relative path when it does not, so a picked *file* can never resolve to another one. A target already in `related` (by resolution, not by spelling) leaves the file untouched, and a `related` the reader cannot take as a list of links is refused rather than replaced. Links run one at a time, in a queue `linkQuestion` holds itself rather than one the caller must remember (the chain is `serialised()` in `packages/core/src/serialise.ts`, shared by every read-modify-write that has this hazard — the page's writes, captures, hand-made stubs, dismissals; each caller makes its own queue, and makes it beside the work rather than taking one from a caller): writing `related` whole means planning from a read, and two links that both read before either wrote would lose one — the hash check cannot catch it, since re-apply faithfully applies operations that were correct when they were computed. The same reason the page has a queue (Position history's two paths); the other triage actions need none, each only setting keys or appending a line.

**Position history's two paths.** Edits on the page: the view saves `## Working answer` with `replaceSection`, diffs the Position against the text it was given, and records the Revision with `prependEntry` under the 30-minute coalescing rule — or, when the save falls inside the window, re-stamps the head entry by replacing `## Position history` whole with every other byte of the section spliced back (#213: the operation set has no "edit one entry", and the section is owned; the same path a why added after the fact takes). The core's `coalesce` is pure and keyed by field, so a later Kind's field inherits the rule. Edits elsewhere (Obsidian, the Vault editor later): the watcher's `positions` diff raises a *pending Revision* and splices it when the file is quiet (§ Watcher and Ingest). Both are in this beat; a history that only saw in-app edits would be the silent failure the brief forbids.

**The two paths meet in one write.** Every page write also carries what the file still owes its history (#217), and the operations apply in order, each located afresh — so a write that both splices a parked entry and replaces `## Position history` whole would write the entry and then erase it with a body computed from the file as read. The order is therefore the write's, not each caller's (`orderOf` in `page-write.ts`, which every Kind's page writes through — #333): the parked splices go first, so the entry a save records lands above them, and after a whole-section rewrite instead, where they still read newest-first because nothing the app wrote can postdate a row still parked — every own write splices what is waiting. A save inside the coalescing window closes it rather than re-stamping when anything is parked, so the rewrite that meets a splice is only ever a why's (#216).

**Navigation.** The window's location is the URL hash — `#/inbox`, `#/question/<vault-relative path>`, `#/research-question/<vault-relative path>`, `#/loose-ends` — the single source of truth for *where*; everything else stays React state, and there is still no store library (ADR 0005, 0010). A hash is copyable, gives the iPad client and a later "open in Vitrine" link an address, and costs nothing over a location value passed down. Surfaces are reached from the Sidebar until Home (beat 12) exists, and objects from the Global command, whose navigation half is #302 (ADR 0021). A Kind-addressed object takes its Kind's own singular name and a surface keeps its own (ADR 0026, #299); every `#/` literal in the renderer's own code is in `router.ts`, so a route added later cannot spell a prefix twice — the suites still hand-spell the Addresses they arrive on, which is what a rename costs.

**An Address that does not resolve lands on the Inbox saying which one it was** (#299, ADR 0027 decision 7). Two arrivals reach it and only one speaks: a hash nobody ever wrote falls through silently — it is indistinguishable from a typo — while a hash under the prefix ADR 0026 retired says so on arrival, and so does one the router accepted whose file the core cannot answer for. The grammar is the app's absence line, *Address — what came back*: `no longer an Address this app uses` from the router, and the core's own reason (`missing from the vault`, `not a Research Question: kind is question`) from the surface that asked. The Research Question view reports its own arrival that way, replacing rather than pushing, which supersedes spec #206 story 55's line on the page. What is *not* an arrival stays on the page and must not move the window: a file removed under the reader, and one that resolved and then stopped being readable — a `kind:` edited in Obsidian, a permission changed — each keep their line where the reader is standing. The view tells the two apart by what the first answer for this Address said, which is why it remembers that. The Address cannot ride in the hash — the canonicalising replace rewrites it to `#/inbox`, which is what makes the landing visible instead of a flash — and it is not app state either: it goes on the history entry (`history.pushState`'s first argument, which `pushRoute` and `replaceRoute` fill from the route), because what it records is a fact about *one arrival*. Going back to that entry says it again; every other entry says nothing; nothing has to remember when to forget. It is kept flat and read one field at a time, because `history.state` hands back a fresh clone per access and a snapshot of the object would never equal the last one.

**A Question's Address is the Inbox with a row named** (#300, ADR 0027 decision 7). `#/question/<path>` is not a surface of its own: the window is on the Inbox either way, so the route is the Inbox carrying the path it arrived on, and `Inbox` is the one component that reads it. Arriving selects that row and puts the keyboard on the list, which is ADR 0010's rule — the surface the object landed in takes the keyboard — reached here by an Address rather than by a capture. The Address is *where to arrive, not a cursor*: nothing writes back to it, so moving the selection afterwards leaves the hash where it is, and a hash that rewrote on every `j` would fill the back stack with rows until *back* stopped meaning "where I came from". A Question that is renamed or removed *under* an open Address is the Inbox's own selection handling and nothing more — the selection follows the rename and clears on a removal, the hash is left alone because the arrival is spent, and nothing is said about the Address. An arrival that finds no row is the unresolved landing above, decided by the first listing that answers and never by a later one: the reason is the vault's own where the file is one it could not read, and otherwise `not a Question in this vault`, which is the whole of what a list of Questions can tell about a path no row bears. A listing that *failed* says nothing at all — the read is what is broken, and it is already on screen.

**The Global command's list is half the renderer's** (#302, `packages/renderer/src/GlobalCommand.tsx`). The core answers with the objects alone, because a Surface is not a file and a hash is not the index's to know; the renderer holds the fixed set — `surfaces.ts`, which the Sidebar draws from too, so the map and the command cannot disagree about what is reachable — filters it by the same rule, and orders across both. Ordering across both needs a score for every row, so the four rungs and the key they compare through exist a second time, in `match.ts`: the two copies have to agree, because a row the renderer scored differently would sort above rows the core had already cut at 50. They are not shared, because nothing can be — `core` is a devDependency of the renderer, types only, and the renderer bundles for a browser. What holds them together instead is `match.pinned.test.ts`, which imports both keys and compares them over a corpus: the whole string is lowercased at once on both sides, because a few mappings are context-sensitive and `ΟΔΟΣ` is `οδος` whole and `οδοσ` character by character — a divergence no test of either side alone could see. What only exists on this side is the marked run, mapped back onto the Display name as it is written, so a query typed across a hyphen marks the hyphen with it; the per-character walk it needs is checked against the key before it is trusted, so the same divergence can only ever cost a highlight and never a row its place. The overlay is one tab stop: the key handler is the input's, so a `⇥` that walked focus out to the Sidebar behind the scrim would leave nothing able to hear `esc`. Reach stays one rule: `routeOf` in `kinds.ts` says where a Kind opens, `addressOf` is that plus `hashOf`, and a Kind with nowhere to open has no row — so no row can lead to a dead end, and a beat that adds a page adds it in one place. A jump is one `pushRoute`, so back returns; closing puts focus back where it was, and whatever the window lands on then takes it (ADR 0010), which is why the restore is unconditional rather than skipped on a jump. The Address the window is already on is listed and marked, and is never the default choice.

**The capture is the last row of that same list, and one index spans both** (#303, ADR 0027 decisions 1, 2 and 8). The destinations occupy `0…n-1` and the capture occupies `n`, so the arrows walk one run and `⇥` jumps between its two halves; there is nothing to reconcile between two selections because there is only ever one. Which half `↵` starts on is the rung of the row it would act on — an exact or prefix hit means a name was typed and `↵` goes, anything weaker means a question was typed and `↵` writes it down — and because an empty query scores 0 everywhere, a freshly opened command is already a capture. The rung is read off that one row and never off the whole list: the rows are sorted by strength, so the first that is not the Address the window is on is also the best `↵` could act on, and an exact hit on the page the user is standing on — which `↵` cannot act on — must not lend its strength to some weaker row they never named. A list holding nothing but that Address therefore falls to the capture too; `⇥` still crosses to that row, because crossing is a choice and the default is not. `⇥` is what the key the paragraph above keeps inside the overlay is now for. The verb is therefore never silent and never has to apologise — where #302 said *you are already here* or *nothing here goes by that name*, it now names the Question about to be written, which is what makes a query that matched nothing read as the ordinary case it is.

**Both chords write through `capture.ts`** — the Provenance chip and `useCapture`, which holds the two rules that belong to the write rather than to either UI: an empty line is not a Question, and one `↵` is one Question. The second is a ref and not the mutation's pending flag, because that flag is only true after React has re-rendered, which is a repaint too late for two keystrokes in one tick. This is what ADR 0027's *only the presentation differs* costs in code: the procedure, the Provenance resolution (`App.tsx`, from the route and never from the chord) and the landing are one, and `CaptureLine.tsx` and `GlobalCommand.tsx` hold nothing but their own drawing of them.

**A keyboard list follows its choice** (#320, ADR 0030). Every list in the app that scrolls is longer than the window it shows — the Global command and the Picker cap at fifty rows in about nine and eight, the Inbox holds every Question in the vault — so the choice has to be scrolled back into view when it moves, or the keys that act on it act on a row nobody can see. One hook does it for all three, `useChosenInView` in `packages/renderer/src/chosen.ts`, and a list that does not call it is a list with this bug. A row is a row whatever stands behind it: the Global command's capture is last of all and has no destination under it, so it is the row the recent set buries most often and the one the choice opens on. Its argument is the element id the list already hands to `aria-activedescendant`: the accessibility tree's own statement of which row the keyboard is on, so the hook cannot disagree with it. What the id encodes is the row's *position* rather than which row it is, and position is what decides visibility — an unchanged id is a row that has not moved, even when a re-read has put a different row in that position. From an effect on that id and never from a key handler — the Inbox's selection also moves on a click, on a capture landing, on an arrival at a Question's Address and on a rename, and the mechanism belongs where the fact changes rather than in each caller that must remember it, as `linkQuestion`'s queue does. `block: "nearest"` is the least scroll that makes the row visible and none at all when it already is, so the rows just read stay put. How far the list then moves is the browser's: jsdom implements no layout, which is also why the renderer's suite carries `src/jsdom-gaps.ts` — it supplies the `scrollIntoView` jsdom leaves off `HTMLElement.prototype`, rather than the app guarding a call whose landing on nothing is the bug.

## Hypothesis view

Beat 3 (map #131, #170), grilled 2026-09-28; the ADR is 0031 and the vocabulary `CONTEXT.md` § Testing. Assumes beat 2's Position history and write protocol and beat 2b's Addresses; this beat contributes `positionsOf` for the Hypothesis Kind and the first caller of `setInlineField`. Markdown-only, and with zero runs: Experiments are beat 4, so nothing here attaches Evidence. Lines found under a criterion are read, which is enough for *edited after evidence* to guard a criterion from the day it is written.

**Promotion** is `h` on an open Question in the Inbox or the same control beside *resolve* on a Research Question page: one typed line for the claim, `↵` to write, `esc` to write nothing, and the new page takes the keyboard (ADR 0010). The Hypothesis is written first and whole; then the Question's `status: promoted` and `promoted_to`, or the Research Question's line under `## Related questions`; a refused second write removes the Hypothesis, as beat 2's promotion does — and so does one that fails outright, one step (`orTakeBack`) serving every promotion's second write. From a Research Question (#332) the second write is `- [[hypothesis]] — sharpened into a hypothesis, <date>` appended under `## Related questions` through the page's own-write queue, so an Obsidian edit still owed the page's history is spliced in the same write; the page keeps `status: open`. Only an open page offers the control, and the core refuses a resolved one as it refuses a Question that is not open — a call #332 made, not the spec: a test hanging off a finished pursuit is reopened first. Both routes run in the questions service's queue (`promoteToHypothesis`, `promoteResearchQuestionToHypothesis`), since both pick a name in `hypotheses/`. A name already taken refuses rather than taking ` (2)` (#331): the claim is the name, and a second Hypothesis claiming the same thing is for the user to decide, not to file beside the first. The Question's rule keeps a trailing `.`, so a claim written as a sentence names its file `….md`. The Inbox legend gains `h hypothesis`; the row's typed line is *answer in place*'s, labelled *Claim*.

**The page** draws the claim, the Derived state with the rule printed beside it and a *because* line naming the clause that applied (TEST-3), the criteria, design notes, and the Position history, with the derived related rail — the object promoted from, and every Question whose `from:` names the page. The claim and design notes are edited in place like a Working answer (#333): one `hypotheses.savePosition` per save, the section and its Revision in one write through the Research Question's own-write path, now `page-write.ts` and shared, so a Hypothesis save and a Revision parked by an Obsidian edit meet in one write exactly as a Working answer's do; the field and the *changed on disk* line are `PositionField.tsx`, the why line takes the page's Kind. An empty claim is refused rather than saved — promotion never writes a Hypothesis without one, and clearing the field is not how a claim is withdrawn; empty design notes are a save. The header's *claim revision N of N · held since …* counts `claim` entries only. In the index's `positions` the criteria are one field, `criteria`, holding `## Criteria` whole (#336) — the history still names each criterion by its label; see *Obsidian's criterion edits* below for why. A criterion is written with a required Relationship and no default. Its chip reads *awaiting evidence* when there is no Outcome; one with an Outcome and no Evidence says no run is named; one with no Relationship says it does not count yet; an Outcome outside the vocabulary says *outcome unreadable* on the criterion, not only in the footer. Delete is offered only while a criterion has no Evidence; after that the page offers *make diagnostic*. The rule is ADR 0031 decision 1, computed in the core from the criteria alone, plus the newest un-voided Override. The fresh page — a claim and nothing else — derives inconclusive, and the *because* line says it is because nothing has been tested, not because the criteria disagree.

**Criterion writes** (#334, `hypothesis.ts`) are four procedures — `hypotheses.addCriterion`, `setCriterionField`, `editCriterion`, `deleteCriterion` — each one write through `writeOwn`, so a criterion write and a Revision parked by an Obsidian edit meet in one write as a claim save does. An Outcome or a Relationship is `setInlineField`, its first caller; adding appends `### <text> ^c<n>`, a blank line and `relationship:: <r>` to `## Criteria` with `appendToSection`; rewording or deleting replaces `## Criteria` whole, naming the criterion by its id and refusing when no criterion carries that id or two do, as a ticked thread refuses. A rewording also sends the text the page read (`was`), since it would otherwise overwrite a rewording made in Obsidian; a delete sends none, because what it removes is only ever judged against the file as re-read inside the queue, and it refuses the moment that criterion carries a line. The next id is `nextCriterionId` beside `nextBlockId` in `vault-files.ts`, which reads `## Position history` as text as well as the file's block ids, so a line typed by hand in the entry grammar still reserves its number. Every write records the criterion's Revision — its field the label as it stood, its `from:` the whole block before (empty for a new one) — under the same thirty-minute coalescing as any field, and a `· state` entry when `derive` on the criteria before and after the change disagree. A value the criterion already holds, or a rewording to the same text, writes nothing. Delete is refused while any line sits under the criterion (ADR 0031 decision 5) — a `refused` error, not `changedAndUnreapplyable`, which a page reads as *changed on disk*. On the page each card carries its Outcome and Relationship as rows of radios — none checked when the file records none — and *edit* and, while nothing tests it, *delete*; *+ criterion* opens a form whose *add* waits for a Relationship to be chosen (TEST-1). A refusal is a line on the card or the form that asked.

**Edited after evidence** (#335, TEST-5) is judged by `revisionField` in `hypothesis.ts`, inside the queue against the file as re-read: a rewording or a Relationship change to a criterion with any line under it is written `· criterion C2 · edited after evidence`; an Outcome never is. A marked entry never coalesces, so each rewording keeps the wording it replaced; and since the suffix is part of the field, an Outcome recorded minutes later opens its own entry rather than absorbing it. The history chains a criterion's entries by its number, so an entry made diagnostic still shows what it became. The page read gives each criterion its `editedAfterEvidence` marks, matched by the id's number so a criterion made diagnostic keeps the mark its old letter earned, each with its `why:` and the wording and Relationship its `from:` held. On the page, *edit* on a tested criterion opens a warning with *save the edit* and *add a new criterion instead*, and blur does not save — reaching for the alternative would otherwise commit the edit it avoids; choosing a Relationship there waits on the same warning. The alternative opens *+ criterion* holding the typing (and, for a relabel, the Relationship chosen). *make diagnostic* replaces *delete* once a criterion is tested, and asks nothing, being the sanctioned way out; the core marks it all the same. The history draws a marked entry on its own, never in the quiet trail, saying *no why written* when none was and always offering one.

**Obsidian's criterion edits** (#336, stories 51, 52, 87) are recorded as the page's own would be. The index diffs `## Criteria` as one Position rather than one per criterion, because the pending-Revision diff counts only a field the file held before and still holds (§ Watcher and Ingest, External Position edits): keyed per criterion, a deletion is a field gone and so no change at all, and a Relationship change moves the label the field was keyed by. The parked row therefore holds the section as it was, and the splice (`splicesOf` in `page-write.ts`, `criteriaEntries` in `hypothesis-rule.ts`) pairs its criteria with the section that came after — the next parked row's `from`, or the file — by the id's number: a changed block is a `criterion <label as it stood>` Revision, suffixed `· edited after evidence` when its text or Relationship moved while tested; a tested block gone is `· deleted after evidence`, an untested one a quiet Revision as the page's delete writes; a new one its first Revision from empty; and a `· state` entry on top when `derive` disagrees across the two, all stamped with the row's time. *Tested* there means Evidence under the criterion at **either** end of the window, where the page judges the moment before its edit: a parked row sees only the two ends of what may have been many Obsidian saves, so a run named and the wording then changed to fit it would otherwise read as an untested criterion reworded — the one move the mark exists for. The rarer honest order (reword, then name the run) is marked too, and offered a why like any marked entry (ADR 0034). A splice that finds no `## Criteria` heading — retyped mid-edit — writes the row unjudged, as a quiet `· criteria` entry holding the section as it was, rather than every criterion as deleted. The rule lives in the core; `derive` and the labels moved to `hypothesis-rule.ts` so the page-write path can use them without importing `hypothesis.ts`, which imports it. Rows parked by an earlier build under a `criterion <label>` field splice as quiet entries, unjudged.

**Override** is reached from the line under the rule, offered once any criterion carries an Outcome, and cannot be completed without a why; the page then reads *supported* with the derived state printed beside it. A write that voids it — any criterion Revision, a criterion added or deleted, a claim Revision — writes the void in the same operation list, and so does the watcher's splice when the cause was an Obsidian edit.

As built (#337): `hypotheses.override` writes `· override`, the why on one line, `from: inconclusive`, through `writeOwn`; it refuses an empty why before the queue and, inside it against the file as re-read, whatever `overrideRefusal` in `hypothesis-rule.ts` says — already live, not inconclusive, no Outcome recorded. The page read's `overridable` is the same function, so the line is never offered for a write the core would refuse. The live Override is `liveOverride`: the newest `· override` carrying a why that no `· override voided` names by its timestamp — one typed by hand without a why is not an Override, and stays in the history, loud, saying so — and `explainRevision` refuses a why onto it, and the history offers none, since nothing it came after has voided it and a why would stand it over criteria it never judged. `derive` takes it and returns `effective` beside `state`, *supported* only while the derived state is inconclusive: an Obsidian edit still parked may have moved the criteria, and a result they reached is not the Override's to contradict meanwhile. It also returns `unlanded`, every criterion keeping the state from supported, which the form lists as what it overrules. The void lives in `writeOwn`, not in each write: a plan that records a Revision of what an Override judged returns its timestamp as `revisesJudged` (every criterion write; a claim save, never design notes), and the splice voids on the first parked `claim` or criteria row that judged a change; when both happen in one write, the splice's void — the older — is the only one. The void sits on top of its write's entries, stamped with them. The history draws `override` and `override voided` loud, the void as *voids the override of <date>*, and a Hypothesis passes it three filters beside *everything* and *explained only*: the claim; criterion edits (every `criterion` entry and an unjudged `criteria` row); and what decided it — each `· state` entry, the criterion Revision stamped with it, and every Override and void.

**Close the loop** is offered when ADR 0031 decision 8 opens it. It is one write into the object promoted from, and a refusal lands as a line on the Hypothesis. The follow-up capture (CAP-5) is offered whenever the state is closable, with `context: resolving` and `from: [[hypothesis]]`; any other capture on the page is `pursuing`. Both are `questions.capture` (#339) — `{ context: "resolving", hypothesis: <path> }` from the page's own *capture what it raises* line under the loop, `{ context: "pursuing", page: <path> }` from either chord — and write the Question alone: the page's Kind is checked before anything is written, and nothing is appended to a Hypothesis. The related rail is `related` on `hypotheses.page`, computed in `readHypothesisPage`: `promoted_from` resolved by `resolvePromotedFrom`, as the loop resolves it (a link that lands nowhere, or on two files, is named with the reason, not dropped), and every Question whose `from:` the index resolves to this page, newest captured first. Whether the loop is closed, and whether the newest line still matches the state, is read from that object through the index.

As built (#338): `hypotheses.closeLoop` in `hypothesis.ts` takes `basedOn` — the result written is the one the page showed — and refuses when `closeRefusal` in `hypothesis-rule.ts` does, when there is no `promoted_from`, and when it resolves to no file, to two, or to a file that is neither a Question nor a Research Question. `promoted_from` is resolved by `resolvePromotedFrom` and a Question written to by `writeToQuestion`, both in `research-question.ts` and shared with a resolved Research Question's write-back, so one broken link is refused in the same words either way; a Question takes `status: answered`, `answered` and the lead line in that one protocol write, whatever its Status, and a Research Question takes its line through its own-write queue. The page read's `loop` is `none`, `unresolved` with the reason, `open`, or `closed` with the newest line's result and date, beside `refusal` — `closeRefusal`'s reason, null when closable, which the page prints where the offer would stand — and `result`, the word closing now would write (`supported (override)` while an Override is live); the page compares the two to say the line no longer matches. The line is found by the parent's wikilinks that the index resolves to this page, then the line's text against one grammar (`RESULT_TAIL`) in the one place the close writes it — the lead (`leadRange` in `question-kind.ts`), or a list item under `## Related questions` — so the *sharpened into a hypothesis* line is never read as a result. The Inbox row reads *answered — <result>*: the index stores `answeredBy`, the newest `Answered by` line in a Question's lead as its link and result (schema 7), and the listing shows the result only while the Question is answered and the link lands on a Hypothesis — so a newer Research Question answer, a reopen, or a line typed about a note shows none.

**Address and name.** `#/hypothesis/<vault-relative path>` (ADR 0026), `hypothesis` in the Global command's `ADDRESSABLE` — between the Research Question and the Question, so a tie is broken page before row — and a Display name from the claim Position rather than frontmatter, falling back to the file name. The file is never renamed when the claim is revised, so every pointer that names a Hypothesis reads its Display name instead of the link it was written as (#340): the Inbox's promoted row says *promoted to* and the claim as its link (`ListedQuestion.promotedTo.display`), and a Research Question's line shows the claim in place of the link's target (`LinkLine.link.resolvedDisplay`). Every other Kind on such a line is still named as written, because there the citekey or file name is what the reader wrote. No list surface; the Sidebar's *Hypothesis view* lights only when one is on screen. With no Hypothesis in a vault read in full and watched, the entry is drawn hollow with *from a research question* beneath it (#347, prototype 12 panel 4) — waiting shown as provenance still to come, never greyed out, so nothing can look broken.

**Adds one Loose Ends row** (§ Loose Ends, `stalled-hypothesis`) **and owes Home nothing.**

## Experiment view

Beat 4 (map #131, #171), grilled 2026-09-28 with beat 4b; the ADR is 0035 and the vocabulary `CONTEXT.md` § Testing. The page is prototype 05: purpose, design, Artifacts inline and large, observations, the hand-set status, and a rail of *where it ran*, *attached as evidence* and the Position history trail. *Related runs*, which the prototype drew, is not built — nothing defines it, and if it means Experiments attached to the same Criteria it can be derived later without a file change.

**Made** on the Experiment surface (*new experiment*: a name, then the page) or from a Criterion that needs Evidence not yet run, which makes the Experiment and attaches it once it has a note. Never promoted from a Question; the Inbox's triage verbs stay five. Address `#/experiment/<path>`; the Kind joins `ADDRESSABLE` and the Picker's Kind glyphs.

**The Experiment Inbox** is derived: `status: complete` and either `## Observations` empty or no Evidence line anywhere naming it. Its two halves are the prototype's *not yet interpreted* and *read, unattached* facets. Nothing clears it; a run leaves by being written up and attached or by being abandoned. The only number is how many runs exist, in the chrome.

**Attaching as Evidence** (TEST-12) has three doors — the page's *attach as evidence*, the Inbox's `E`, and a Criterion on the Hypothesis page — and one write: `appendToSection` under `^c<n>` of `- [[<name>]] — <note>`, the note required. It is a Revision of that Criterion (ADR 0031 decision 4), so it voids a live Override as any criterion Revision does, and it records no Outcome. The Picker is narrowed to Criteria, grouped by Hypothesis with falsifying ones first. Before the write, each linked Artifact is checked (TEST-13, ADR 0035 decision 6) and the result shown beside the attach, never blocking it.

**Stored or linked** (KEEP-9): under 25 MB is proposed as stored, heavier as linked with the brief's warning, and either is overridable per Artifact at the moment it is added (ADR 0035 decision 4). A CSV shows its first rows, an image at the column's width; anything else is a named card.

**Capture from a run** (CAP-6) is the Capture line's own Question with `from: [[<name>]]` and `context: observing` — the same object every other capture writes (CAP-8), and nothing written onto the Experiment.

As built (#364): `experiment.ts` in the core, under the router's `experiments` namespace. `from:` and a closed loop's line on the Inbox row both resolve through `landing` in `link-text.ts`. `create` trims the name, strips the folder's by the Question's rule (`fileName`) with no id fallback — a name with nothing left to file under is refused, since an id is not a handle the user's code knows — and claims the folder with a `mkdir` that fails on one already there, so a taken name is refused whether the folder holds a page or only files (a script's plots are not the new run's), and macOS's case-insensitive disk catches `Sweep-7` beside `sweep-7` without a comparison here. It runs in its own module-scope queue. `name:` is the Display name and the Kind is in `ADDRESSABLE` between the Hypothesis and the Question. `page` reads the six sections, *where it ran* as `label: value` lines (a colon followed by a space or the line's end, so a bare URL is a value), `status` with one outside the four kept verbatim as `statusUnreadable`, and `from:` resolved as `cameFrom`. `saveSection` is `saveEditedSection` in `page-write.ts`, now shared with the Research Question's; `setStatus` is one `setFrontmatter` through `writeOwn` and writes nothing for the status already held. In the renderer, `#/experiments` holds only the *new experiment* line until the Inbox (#371); the page's Purpose and *where it ran* are `PositionField`s with `withWhy={false}`; *where it ran* is drawn as its labels and values (the page read's `lines`) and opens as text on *edit*, closing again through the field's `onDone` once nothing is left in it. Purpose takes the keyboard only on the arrival that made the run — `App` carries that one-time intent, as it carries Loose Ends' *attach a source* — and `usePageFrame` now leaves the keyboard with a field inside the page that took it. The rail's entry keeps its link while hollow, since the surface is where the first run is made; it is drawn with the rail's hollow dot, not prototype 13's `▽`, because the rail draws no Kind glyphs for any entry yet. Design, Artifacts and Observations are drawn as the file holds them until #365 and #366.

## Loose Ends

The shell lands with beat 2 and every later beat's spec names the rows it adds. Four groups in the brief's order; counts per group, never a total; a group with no rows is not shown at all. Every row carries its one-click resolutions and *mark deliberate*, which writes `dismissals.json` keyed by the object's `id` (or path, for a Note). Reads are index queries, and the rows are never stored; the one input kept outside the index is the record of open days below.

**Quiet periods are counted in open days** (#243, from stories REP-11 and RES-3 in the story tree at tacomancy.com/vitrine_stories/). A threshold like the stalled row's is a number of distinct open days counted strictly after the date the clock starts from — never calendar days. A week or a month away then adds nothing to it by construction, so an absence can change how much Home has to say but never creates a row that was not there when the user left. The core records the local date in `queue.sqlite`'s `open_days` (`day TEXT PRIMARY KEY`, `YYYY-MM-DD`) on `vault.open` and when the shell reports that the window gained focus (`focused`, over the `utilityProcess` channel) — not on any request, because the renderer re-queries on `vaultChanged` and an app left open unattended while a sync client delivers files would otherwise count every day. A date is a fact about the past that no sweep could recover, which is what the database's charter is for; the table raises `queue.sqlite`'s schema to 2, and a version-1 queue is migrated by creating it, never refused. Dates are compared as strings: an open day as it was recorded in the machine's zone then, `promoted` as the date in its own written offset — travel can shift a count by one, which a threshold in weeks absorbs. Days before the table existed are not there, so a Question promoted earlier counts from the first recorded day and surfaces late rather than early. Tests inject the threshold, the recorded days, and today through `AppOptions.now`.

**A row is as coarse as a dismissal is** (#224). *Mark deliberate* is keyed by an object and a row kind and by nothing finer, so two rows about one object under one kind could not be silenced apart — clicking either would quietly take the other, which is the loss the per-row-kind rule exists to prevent. The ambiguous-link row is therefore one row per *linking file*, listing every name in it that reached more than one file, rather than one row per link; a name written twice in a file, or in two casings, is one entry. Any later row kind owes the same check: if a row cannot be dismissed on its own, it is not a row, it is a line inside one. A dismissal keyed by a path is re-keyed by the watcher's rename pairing before the `vaultChanged` that carries it leaves the core (§ Watcher and Ingest, Renames), so no listener re-reads the dashboard in the window where the row would be back. A `dismissals.json` that does not parse is not rewritten by a rename either — the other dismissals in it are what the user would lose — and the row returning under the new name sits beside the problem line the dashboard already carries.

**A row opens what has an address.** A Research Question and a Question have one; every other Kind — a Note, a Source, a Source stub, and the ones with no surface at all yet — does not, so the row names the file and stops (spec #206 story 56 — the Vault editor is beat 11). One function in the renderer builds it from the Kind (`addressOf` in `kinds.ts`), so the Research Question view and Loose Ends cannot come to differ about the same file, and a Kind gains its Address in one edit.

**A resolution that changes state is undoable while its row is on screen** (#266). *Mark deliberate* — the only such resolution today — leaves the row in place rather than removing it: the row's reason gives way to what happened (*marked deliberate — permanently out of this list, still in the vault*, prototype 9's words), whatever detail it was carrying is put away — the ambiguous-link row's list of names, since *which two?* is answered once the row is marked — *undo* is its only action, and the group's count, which counts the open rows, drops by one and returns with the undo. The write lands in `dismissals.json` at the click, so the row is gone on the dashboard's next read — whatever prompts that read, a return to the dashboard or a `vaultChanged` while it is open. The undo is for the moment after the click, not a history. A refused resolution — the undo's or the dismissal's — is a line on the row it was about rather than on the page, because what the refusal is about is the state that row is showing. `undismiss` beside `dismiss` removes that one row kind for that subject, drops a subject whose last kind is gone, goes through the same queue inside `dismissals.ts`, and refuses an unparseable file in the same words. Because the undo lives on the row shell rather than in a row kind, every row a later beat adds inherits it. The marked line is drawn in the data voice — mono, muted — rather than prototype 9's teal: the app has no status colour anywhere yet, and a green line reads as congratulation on the one surface whose brief rules out cheerful states. What marks the row is that its reason is gone and *undo* is all that is left. This settles Loose Ends alone: undo for machine proposals (prototypes 06 and 11) is still undecided, and #255 is where that grammar is named.
