# 0008: Markdown is located and spliced, never re-serialised; one grammar package shared by core and renderer

**Status:** Accepted

ADR 0006 decision 11 committed the app to surgical writes — rewrite the frontmatter block and the sections it owns, leave every other byte of a user-edited file identical — and left the parser that makes that possible as the first open item in `docs/architecture.md`, together with the tag grammar the tag tree shares with it. This ADR settles both after a `grill-me` pass. The core never serialises a Markdown document it did not create: the parser is a **locator** that returns byte ranges and structure, and every write is one of a **closed set of semantic operations** spliced into the original text at freshly located ranges. Obsidian's syntax — tags, wikilinks, block ids, inline fields, the frontmatter fence — lives in a fourth workspace package, `packages/markdown`, pure TypeScript with no Node APIs, imported at runtime by core and renderer alike so that a tag the editor colours and a tag the index counts are the same tag. Tag identity is case-insensitive as Obsidian's is. The grammars, the operation set, and the outline the parser returns are `docs/architecture.md` § Markdown.

## Decisions

1. **Locate-and-splice.** Parse for positions, not for a tree to print back. "Every other byte identical" then holds by construction rather than by a serialiser's good behaviour, and the parser need not be a lossless model — it needs offsets and structure. New files (a captured Question, a promotion, an app-created Note) are the only documents written whole.
2. **A closed set of write operations**: set frontmatter keys (order preserved, new keys appended, never a removal); replace an owned section; prepend an entry to an owned section; append a line at the end of the file; create a file. Every write in `docs/architecture.md` § Vault layout is one of these, and Notes are only ever created. Anything that does not fit is a design change that reopens this ADR, not a sixth operation. The set is what makes the next decision possible.
3. **Optimistic concurrency, semantic re-apply, verify after splice.** A write carries the content hash it was computed from. Before the atomic write (temp file in the same folder, rename) the core re-hashes; if the file changed, it re-reads and re-applies the *operations* — an operation finds its target again where a string patch cannot — then re-parses the result and checks the outline still holds (frontmatter parses, `kind` unchanged, each owned section present once). A write that cannot be re-applied or fails verification is not written and surfaces with a reason. Obsidian does not honour locks, so there are none.
4. **micromark, as a locator only.** `mdast-util-from-markdown` for CommonMark with node offsets; `remark-stringify` is never imported. The CommonMark parser is bought for one reason: knowing that a `#` or a `[[` sits inside a code fence, a code span, or a link destination is the part of tag and link recognition a hand-rolled scanner gets wrong one bug at a time.
5. **Our own four syntax extensions** — tags, wikilinks, block ids, `key:: value` inline fields — written against Obsidian's documented grammar. Third-party hashtag and wikilink extensions are someone else's reading of that grammar, with resolution opinions of their own; the day one disagrees with the fixture corpus we would be forking it.
6. **`yaml` (eemeli) for the frontmatter block.** Its Document model preserves comments, key order, blank lines, and the quoting of untouched scalars when a key is set and the document stringified — which is what "rewrite the block, preserve key order, append new keys" asks for — and it quotes values containing `[[`, which Obsidian requires for links in properties. `gray-matter` re-dumps through js-yaml and loses all of that. The fence itself is located by the parser, not by `yaml`.
7. **`packages/markdown`, a fourth workspace package.** It exports grammar *functions* (is this a tag, canonicalise it, parse this wikilink, this block id, this inline field, the fence rule), the micromark extensions built on them, and the outline types the core returns. Nothing Vitrine-specific: which `##` sections are owned, what `^c<n>` means, how a Revision line is shaped are rules the core's modules apply to the structure the package returns. The renderer imports it for the tag tree and, when the Vault slice chooses an editor, wraps the same functions for that editor's parser. dependency-cruiser enforces that the package imports neither side. This narrows ADR 0005's three-package topology without crossing its boundary: the package touches no Node API and no file system.
8. **Tag identity is case-insensitive; display follows the vault.** Canonical form is Unicode NFC then `toLowerCase()`; `_` and `-` stay distinct. Frontmatter `tags:` and inline `#tag` are one citizenship, with the source of each occurrence recorded. Display casing is the majority form *per path segment*, so a parent node has one name whichever child you came from. The app writes tags in the display casing, never introducing a variant; a new tag is written as typed. When it adds a tag to a file whose `tags:` is a legacy string form, the value becomes a block sequence — what Obsidian's own Properties editor and Format Converter do. Tags Obsidian would reject are not tags for the tree or Coverage, but the index records them as invalid with their position so a typo cannot make Coverage lie by omission.
9. **Link resolution surfaces ambiguity.** A bare `[[name]]` resolves by basename, case-insensitively, anywhere in the vault; a target containing `/` resolves by vault-relative path; `#Heading` and `#^block` narrow within the file; `|alias` is display only; Markdown links `[text](note.md)` are indexed as links. Two files sharing a basename make a bare link *ambiguous*: it resolves to nothing, is recorded as such, and is a Loose Ends row with a one-click fix. Obsidian's tie-break is undocumented ("the best match"), so there is nothing to mimic and guessing would be a silent failure. Vitrine writes wikilinks only.
10. **Owned sections are exact.** `## <name>`, level 2, case-sensitive, spanning to the next level-1 or level-2 heading or end of file. Absent when the app must write: appended after a blank line at the end of the file — the user may have reordered the file deliberately, and appending is the one placement that cannot be wrong about that. Present twice: the first is owned, the second is left alone, and the duplicate surfaces. A heading the user renamed is no longer the app's section.
11. **Block ids.** The locator extracts every block id in the vault, app-written or not; the app never rewrites or moves a user's; the per-Source `h` counter starts above any `^h<digits>` already in the file. The `h`/`c` prefixes from ADR 0006 stay: the counter rule makes collision a non-event.
12. **A file that lost its shape is a row, not a wall.** When an app-owned Kind is missing structure its module expects — no `## Criteria`, a criterion without `^c<n>` — the read reports a *shape problem* in the channel #105 already uses for partial and unreadable files, and derived state is computed from what parses. Derived state is never computed from a misread file presented as authoritative; equally the file never disappears.

## Considered options

- **Parse to an AST, mutate, print.** Rejected: ADR 0006 already rejected re-serialising whole files, and `remark-stringify` demonstrably reformats (setext to ATX, `+` bullets to `*`).
- **markdown-it.** Rejected: tokens carry line ranges, not character offsets; a locator needs offsets.
- **A hand-rolled line scanner.** Rejected: it accumulates the CommonMark spec's context rules — fences, indented code, HTML blocks, link destinations — one bug at a time.
- **`gray-matter`.** Rejected: last published 2021, js-yaml underneath, drops comments and quoting on write.
- **Third-party micromark extensions** for hashtags, block ids, wikilinks. Rejected, decision 5. `remark-obsidian` is additionally GPL-3.
- **Grammar in the core only, renderer asks over RPC.** Rejected: syntax highlighting as a network call.
- **Two copies of the grammar kept in step by tests.** Rejected: the drift ADR 0006's "tests are the interface contract" exists to prevent, not to enable.
- **Case-sensitive tags.** Rejected: the vault would disagree with Obsidian about its own tags.
- **Write tags in canonical lowercase.** Rejected after being proposed in the interview: the app would introduce a second casing into a vault whose convention is `#ML/Probing` and could flip the majority display it is supposed to follow.
- **Display first-created casing, as Obsidian does.** Rejected: that is temporal state in Obsidian's cache, not derivable from the files; approximating it means reading an undocumented cache format for a cosmetic match.
- **Resolve an ambiguous link to the first match in path order.** Rejected: a silent failure.
- **Insert a missing owned section at its canonical position.** Rejected: it presumes the user's ordering was accidental.
- **Treat missing structure as empty.** Rejected: derived Hypothesis state from a file the app misread, presented as authoritative.
- **Lock files.** Rejected: Obsidian does not honour them.
- **A `prototype/` branch before writing.** Not needed: unlike ADR 0007 there is no runnable unknown gating the decisions. What this ADR needs is a dozen small facts about how Obsidian actually writes files, which only Obsidian can supply — a committed fixture corpus created by hand in Obsidian, plus the gitignored real-vault snapshot as a second, uncommitted test bed.

## Consequences

- **+** No write the app makes can alter a byte it did not mean to; a refused write comes with a reason.
- **+** One grammar, one identity for tags, at both ends of the RPC boundary.
- **+** `yaml`'s round-trip leaves Obsidian's Properties formatting alone except for renormalising 4-space indent to 2 and the spacing of flow lists — the corpus shows whether that ever churns a real file.
- **−** Four syntax extensions are ours to maintain against Obsidian's grammar, and that grammar is only partly documented: which inline contexts exclude a `#`, whether `#tag/` or `#a//b` is a tag, whether a `tags:` entry containing a space is split or rejected, and whether `[[note#^c1]]` resolves when the id sits on a `###` heading line (ADR 0006 decision 2 assumes it does; if the corpus says no, that ADR gets a dated update moving the id to the line below). The corpus issue, #112, lists each.
- **−** Display casing diverges from Obsidian by design (decision 8, first-created versus majority); a vault with mixed casing shows the majority here and the first-typed there.
- **−** The write-back line at the end of a Question (operation four) is a body write outside an owned section, safe under ADR 0006 decision 11 only because appending modifies no existing byte. It is the one place the closed set touches the user's prose.
- **−** Obsidian strips a BOM on open; the app preserves whatever is there. Line endings and the trailing newline are preserved from the file as read; new files are UTF-8, LF, one trailing newline.
- The editor for the Vault surface is deliberately not chosen here. It must consume `packages/markdown`'s grammar functions; `@lezer/markdown`'s `MarkdownConfig` is the expected wrapping point, and the only Obsidian-flavoured lezer grammar on npm dates from 2022, so that wrapping will be ours too.
