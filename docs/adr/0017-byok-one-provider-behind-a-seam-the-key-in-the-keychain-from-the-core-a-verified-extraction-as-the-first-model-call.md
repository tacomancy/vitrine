# 0017: BYOK — one provider behind a seam, the key in the Keychain from the core, and a verified extraction as the first model call

**Status:** Accepted

Beat 7 of the phase-1 map (#131) adds Watched sources to the Scouts ADR 0016 built for arXiv, and with them the first model call: extracting a Proposal card from a page (`design-brief.md` § Proposals: "the one place in the Scout pipeline a model call earns its keep"). The brief fixes BYOK — "no credentials leave the device except to the configured provider" — and nothing else; this ADR, from wayfinder ticket #139, decides the provider, where the key rests and how the core reaches it (research #135), what the model is asked for, how a bad extraction becomes Source health rather than a quiet field, and what a run records for Scout Activity. The shape: **Anthropic only, behind a `ModelProvider` seam**; **`@napi-rs/keyring` in the core behind a `CredentialStore` seam**, one Keychain item per provider, read at every run; a **feed when the page has one, the model only when it does not**; a structured-output request over **exactly the card fields, all nullable, copy-never-compose**; every returned title and url **verified against the fetched text**, with three new error kinds so a hallucinated card and a missed listing are both *broken*, never quiet. Numbers, schema, and columns are `docs/architecture.md` § BYOK and watched sources.

## Decisions

1. **One provider, Anthropic, called through `@anthropic-ai/sdk`, behind a `ModelProvider` seam with one implementation.** "Pluggable" means a second provider is an implementation beside the first, keyed by its provider id in the Keychain — not a provider picker, and not an OpenAI-compatible base-URL field that ships a surface nobody has tested. The default model is `claude-opus-5` at `effort: low` (extraction is copy-work, not reasoning); the model id is an editable text string beside the key, never a dropdown that has to track the provider's catalogue. A cheaper model is the user's choice, visible in the run's token accounting (decision 8), not a default made for them.
2. **The key rests in the login Keychain as a real credential, written and read by the core through `@napi-rs/keyring`, behind `CredentialStore { get, set, delete }`.** Research #135's recommendation as written: the core makes the model calls (ADR 0005), so the credential belongs to the core's process; `safeStorage` is main-process only and would route the secret through the shell to reach a module for no gain; `keytar` is archived; the `security` CLI puts the secret on `argv`. Service `Vitrine`, account = provider id (`anthropic`), `AsyncEntry` so a Keychain prompt never blocks the event loop. The key is read from the Keychain at each run and never cached in memory between runs, so removing it in Keychain Access takes effect on the next run without a restart. Tests pass an in-memory store; the real one is constructed once in `start.ts`, beside `appSupportDir`.
3. **No key is a state, not an error, met at the point of need; there is no Settings surface.** A Credentials panel — provider, a key field that never echoes the stored value, model id, *test* (one minimal call), *remove* — opens from the app menu and from the Scout form's *Add a key* link, which the form shows inline when the source is a Watched source and no key exists. A Scout with a Watched source and no key is **blocked on credentials**: a distinct health state, not *broken* — nothing failed, something is missing. A locked Keychain or a denied ACL dialog is a fault and is shown as one, never collapsed into "no key". A Settings surface was rejected: a ninth surface the brief never lists, holding one thing.
4. **The key crosses loopback once, on `credentials.set`; nothing reads it back.** The RPC surface is `credentials.status(provider) → present | absent`, `set`, `delete`, `test`. There is deliberately no `credentials.get`; the panel shows only *a key is stored*. The phase-2 iPad client gets the same RPC and the same guarantee: it never holds the key, the core signs the request. This makes "no credentials leave the device except to the provider" a property of the API rather than a promise.
5. **A Watched source is one URL; a feed is read deterministically when the page advertises one, and the model is called only for a page without one.** Feed autodiscovery (`<link rel="alternate" type="application/rss+xml|atom+xml">`) runs on every fetch; a feed's entries map to the card without a model call, cost nothing, and cannot hallucinate. The model path is the brief's sentence taken literally: the page *without* a feed is the one place a model call earns its keep. One fetch and at most one model call per run; no link-following. Crawling is out of scope. Pages-only and feeds-first-as-their-own-beat were both rejected: the first pays for pages that publish a feed, the second makes a beat out of a parser.
6. **The model is shown reduced text and asked for exactly the card fields through structured output.** The core fetches the page, reduces HTML to text with links (scripts, styles, and navigation stripped), and caps it at a token budget, recording `truncated` on the run when it does. The request uses `output_config.format` with a JSON schema — `items[]` of `title, authors[], date, venue, keywords[], abstract, url`, every field nullable — and a system prompt that says *copy, never compose: each value must appear on the page; null when it doesn't.* The schema is the contract with the brief: "missing shows as missing" is a nullable field, and "no model-generated summary" is the absence of a field the model could fill. No prefill (removed on current models), no refusal fallbacks (a fallback bills the user for a model they never chose; a `refusal` stop is a `model` failure with its category in the message). SDK default retries stay.
7. **Every returned item is verified against the fetched text, and three error kinds make the model's failure modes distinct states.** An item whose non-null `title` and `url` do not both occur literally in the reduced text is dropped and counted as `unverified` on the run. To ADR 0016's `network | http | rate_limited | parse` this beat adds **`credentials`** (no key, or the provider answered 401 — *key rejected* is distinct from *no key*), **`model`** (provider error after retries, a refusal, a schema violation), and **`extraction`**. A run is `extraction` when fewer than half of the returned items verify, *or* when it returns zero items while at least half of the last `ok` run's verified titles still occur in the new text — the listing is still there and the model missed it. Zero items with those titles gone is a page that really changed: also `extraction`, message *structure change*. Each run stores the reduced text's hash and length so the comparison has a baseline. **An unchanged hash is `ok, new = 0` with no model call at all** — an unchanged page is the quiet field by definition and costs nothing. The brief's "structure change detected" is therefore an `extraction` failure on a Scout with a prior `ok` run that found items — derived from run rows like everything else in health (ADR 0016 decision 10), so Home, Loose Ends, and Scout Activity cannot disagree. A model-reported confidence score was rejected: it is the model grading its own work.
8. **A run records its model, tokens, and the cost at that day's prices.** `scout_runs` gains `model`, `input_tokens`, `output_tokens`, `cache_read_tokens`, and `cost_usd` computed at run time from a dated price table in `docs/architecture.md`. Dollars stamped at the time of the run are what was spent; pricing at display time rewrites history when prices move. Scout Activity (beat 9) sums per Scout, per run — the brief's words.
9. **A Proposal is identified by a `source_key`, and a page's first run is Retroactive.** `proposals.arxiv_id` becomes `source_key` = `arxiv:<id>` | `doi:<doi>` | `url:<normalised url>`, in that precedence, with the arXiv id extracted from an item's url when the link is an arXiv link — so a lab page and the arXiv Scout produce one card with two Appearances, Corroboration's mechanism for the second source exactly as ADR 0016 decision 7 anticipated. Merging on normalised title stays in the fog. A page has no date window, so "new" is a `source_key` never seen; the first run proposes everything on the page, stamped `origin_retroactive` so the batch can be triaged or rejected with *reject this run*, and the form's *also search back to* is hidden for a Watched source. A first run that records without proposing was rejected: it makes a new Scout silent for weeks.
10. **Fetch etiquette is part of health.** The core identifies as `Vitrine/<version> (+https://tacomancy.com/vitrine)`, honours `robots.txt` Disallow — recorded as an `http` failure with the message *disallowed by robots.txt*, so a Scout a site has asked not to crawl is *broken* with a reason rather than quiet or quietly rude — with a 30 s timeout, a 2 MB response cap, and no retries within a run: the next due run is the retry.
11. **This beat adds two Loose Ends rows and one Home count.** *Broken plumbing* gains *blocked on credentials* (resolving to *open Credentials*) and *structure change detected* (resolving to *open the page* · *run now* · *pause*); the existing failed-Scout row shows the new error kinds. *Blocked on credentials* joins Home's owed *broken Scouts* count (beat 12), though its copy keeps the two apart.

## Considered options

- **Two providers with a picker; an OpenAI-compatible base URL.** Rejected, decision 1.
- **`safeStorage` through a Host round-trip; `keytar`; the `security` CLI.** Rejected, decision 2 — research #135 has the comparison.
- **Caching the key in the core between runs.** Rejected, decision 2: *remove* in Keychain Access would not take.
- **A Settings surface.** Rejected, decision 3.
- **`credentials.get`.** Rejected, decision 4.
- **Pages only, or feeds first as their own beat.** Rejected, decision 5.
- **Model-reported confidence; a text-length delta as "structure change".** Rejected, decision 7: the title-persistence check asks the brief's question — did what we found last time stop being findable?
- **Refusal fallbacks.** Rejected, decision 6.
- **Cost priced at display time; tokens with no dollars.** Rejected, decision 8.
- **`arxiv_id` kept with `url` as a second unique key.** Rejected, decision 9.
- **A first run that records without proposing; a per-Scout "propose existing items" switch.** Rejected, decision 9.
- **A distinct `blocked` error kind for robots.txt.** Rejected, decision 10: the reason is a message, not a kind three surfaces would have to render.

## Consequences

- **+** The BYOK invariant is enforced by shape: the credential lives with the process that uses it, there is no RPC that returns it, and the only outbound call carrying it is the provider's.
- **+** A hallucinated card cannot reach the Queue silently — verification drops it and the run says so — and a page whose listing the model missed is *broken*, not quiet. The invariant "a broken Scout must never look identical to a quiet field" holds for the model path by mechanism, not by hope.
- **+** A lab page with a feed costs nothing; an unchanged page costs nothing. The model is called only when there is something new to read and no cheaper way to read it.
- **+** `source_key` makes the arXiv Scout and a lab page corroborate each other from day one, with no migration when a third source arrives.
- **−** One native dependency (`@napi-rs/keyring`) in the core: the `.node` binary rides in `extraResources` unpacked (`docs/architecture.md` § Packaging already has `asar: false`), and macOS will show the Keychain *Allow / Always Allow* dialog once whenever the calling binary changes — an Electron upgrade in development, the first packaged build under `com.tacomancy.vitrine`. Expected, documented, not a bug.
- **−** Verification demands verbatim presence, so a page that renders titles through JavaScript the fetch never runs extracts nothing — and reports it as `extraction`, which is the right answer: the user learns the page needs a feed or a different URL, rather than trusting invented cards. No headless browser in this beat.
- **−** The cost table goes stale; a run's `cost_usd` is as accurate as the table was on that day, which is what the column claims and no more.
- **−** `CONTEXT.md` **Source health** and **Retroactive** widen: three more error kinds, and a first run counts as Retroactive for a Watched source.
- The beat's spec carries: the seams and the Keychain item, the Credentials panel and RPC, feed autodiscovery, the reducer and budget, the schema and prompt, verification and the three kinds, the hash short-circuit, `source_key`, the run columns and price table, fetch etiquette, and the two Loose Ends rows. Its first ticket should be key → fetch → extract → verify → Proposal with no panel beyond *Add a key*, because that is the tracer bullet.
