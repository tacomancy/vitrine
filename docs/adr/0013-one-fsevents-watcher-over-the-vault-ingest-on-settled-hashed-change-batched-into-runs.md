# 0013: One FSEvents watcher over the vault; Ingest fires on settled, hashed change and is batched into runs

**Status:** Accepted

The brief makes Ingest something the file does to the app, never the user (`design-brief.md` § Ingest review: "Ingest happens when a PDF changes on disk, not when I ask for it"), and ADR 0006 and ADR 0007 each left the mechanism a list of requirements: recognise the app's own writes by content hash, treat an evicted PDF as unreadable-not-changed, FSEvents not polling, decide what a Vitrine write landing while the iPad holds the file means, decide whether a note edited to begin with `Q:` after the fact becomes a Question. This ADR settles all of it after a `grill-me` pass. The shape: **one recursive `fs.watch` over the vault root** — libuv's FSEvents backend, no native module — plus a second over the PDF folder's real path, because FSEvents does not follow the symlink ADR 0006 puts there. Its events are treated as *hints*: every event is followed by a stat, and a stat that disagrees with what the app last recorded is followed by a content hash, so the app's own writes and iCloud's re-downloads fall out of the same comparison rather than needing a registry of expected writes. A file is acted on only once it has been **quiet for a settle window**, and everything that settles together is **one Ingest run** with one summary line. Two consumers hang off the same watcher: **Ingest** for PDFs, the **vault index** for Markdown — the latter also raising a pending Revision when a Position is edited outside the app. What the watcher cannot see (the app was closed, the Mac was asleep, FSEvents overflowed) a **stat-only sweep** catches up. The exact rules, numbers, fields, and event types are `docs/architecture.md` § Watcher and Ingest.

## Decisions

1. **One watcher, two consumers.** The Markdown side needs the same mechanism — #105 lists the vault "at open time" and defers a live watcher; § Vault layout says Obsidian edits to a Position are recorded "the same way"; ADR 0006 re-keys Note dismissals on observed renames — so this ADR settles the watcher once, with Ingest and the index as its two consumers, rather than deciding the settle window, the own-write filter, and the catch-up sweep twice. The Position history *write* stays owned by that slice; what this ADR fixes is when the watcher raises it and when it is spliced (decision 10).
2. **Node `fs.watch({ recursive: true })`, nothing native.** On macOS it is libuv's FSEvents backend. Its events are coarse — verified: a fresh write, a temp-file rename, and a folder create all arrive as `rename`, and the first event after opening is noise — so the pipeline never trusts the event kind. Since every event is stat-and-compared regardless, a watcher with a richer vocabulary (`@parcel/watcher`) buys nothing, and would be the repo's first native module, rebuilt per Electron ABI forever.
3. **Catch-up is a sweep, and the sweep is stat-only.** `fs.watch` exposes no FSEvents history, so a PDF annotated on the iPad while the Mac was asleep is found by a sweep that stats every file and compares to what the app recorded: at vault open, after a watcher error or overflow, and — the PDF folder only — whenever the window regains focus, which is the moment the user has just come back from the iPad. Ordering on open is *start watching, then sweep*, so nothing written during the sweep is missed; a file both swept and evented no-ops through the hash. Not a timer: that is the polling ADR 0006 ruled out, and it would fire while the user is reading.
4. **Change identity is stat, then hash.** Per file the app records `{ size, mtime, hash }` — in the sidecar for a PDF, in `index.sqlite` for Markdown. On an event or sweep: stat; if size and mtime match, nothing; else hash (SHA-256 from `node:crypto`, ~50 ms for a 30 MB PDF, no dependency); if the hash matches the last-ingested or last-written hash, record the new stat and nothing — an iCloud re-download, a touch, the app's own rename landing; else the file changed. An always-hash rule was rejected because a sweep would then read every PDF, which *materialises* the evicted ones (decision 6).
5. **Settle, then batch.** Preview, iCloud, and Dropbox all write in several steps, and a reconnecting sync client delivers fifty PDFs at once. A file is acted on only after a settle window with no events and two stats agreeing; everything that settles inside one run window is one Ingest run, one summary line, one panel at most. Per-file Ingest is correct and would make the Monday-after-a-week-away case (`design-brief.md` § Home) fifty notifications — the click-through habit § Ingest review is designed against. The numbers (2 s, 5 s) are code, recorded in § Watcher and Ingest as starting points.
6. **An evicted file is unreadable-not-changed.** Node's `fs.Stats` carries no `st_flags`, so `SF_DATALESS` is not directly readable; `blocks === 0 && size > 0` is the tell. Such a PDF is neither hashed nor ingested and its sidecar is untouched; when the Reader opens it, the core's read materialises it and the resulting events no-op through decision 4. Proactive materialisation at open was rejected: it downloads the whole folder at the moment iCloud is least likely to have finished syncing it, and defeats eviction on a laptop. The heuristic is confirmed against a real evicted file as an acceptance criterion of the first Ingest ticket — nothing here can safely produce one.
7. **A conflict copy is a decision, not a Source.** Vitrine writes a highlight on the Mac while Preview on the iPad holds the file; the iPad saves; the sync service resolves by creating `klinzing2019 (conflicted copy).pdf` or `klinzing2019 2.pdf`. A *new* PDF whose document fingerprint (ADR 0007 decision 9) matches an existing Source is never ingested as a Source: it is a Loose End under *Broken plumbing* with two resolutions — *use this copy* (it replaces the canonical file, and the next Ingest re-matches every identity through the tiers, so nothing is lost silently) or *discard it* (Trash). Merging the two annotation sets automatically was rejected: a fourth PDF-writing path for a rare case, silently choosing which side wins on an annotation both edited.
8. **The `Q:` rule runs on every Ingest.** It is evaluated against each annotation's *current* note, and the sidecar records `question: <id>` once it has spawned one. A `Q:` added on a later pass spawns a Question on that Ingest; an identity that already has one never spawns a second; editing the `Q:` text afterwards does not rewrite the Question — it is the user's now, and its Provenance still points at the annotation; removing the prefix does nothing. "First Ingest only" was rejected because it makes a typo in the convention permanent, the exact failure § Ingest review names.
9. **Renames pair by content hash within a batch, for Notes and PDFs only.** `fs.watch` reports a rename as two unrelated events. A vanished path and an appeared path with the same hash in one batch are one rename: a Note's dismissal is re-keyed; a PDF's Source gets `pdf:` updated with `setFrontmatter` — the watcher's one write into a Source, and an own write the filter then ignores. App-owned Kinds need none of this; they are keyed by `id:` and the index re-parses. Unpaired cases are honest: vanished alone is removed from the index, appeared alone is new. A rename that also edits the file (Obsidian's rename-with-heading-update) falls out as delete-plus-create and a dismissed Note becomes the orphan row it now is — correct for a Note whose content changed. Inodes were rejected for pairing: iCloud and Dropbox replace them on their own writes.
10. **A Position edited outside the app becomes a pending Revision, spliced once the file is quiet.** The `from:` text is captured from the index *before* the first change, with that change's timestamp, and held in `queue.sqlite`; it is spliced into `## Position history` when the file has been quiet for the 30-minute coalescing window ADR 0006 already set for in-app edits, or on the app's next write to that file, or at vault close, whichever first. Splicing on settle — a write under the user's cursor every couple of seconds while they type in Obsidian — was rejected. `queue.sqlite` because a crash before the splice must not lose what the text changed from; that is the "not re-derivable" state the database exists for.
11. **One event stream, with the bearer header on it.** The renderer subscribes once, to a discriminated union — ingest landed, vault changed, vault switched, later Scout finished — and its reaction to a vault change is query invalidation, so per-concern subscriptions would all end at the same call. `EventSource` cannot send a header and the token never travels in a URL (§ Decided, shell ↔ core), so the subscription client is a `fetch`-backed `EventSource` implementation carrying the bearer header — tRPC 11's `httpSubscriptionLink` accepts one. The first ticket verifies that; the named fallback is a plain Hono SSE route read through `fetch` and a `ReadableStream`, which costs tRPC's typing on that endpoint and nothing else. A cookie (a second home for the token) and a one-shot `?ticket=` (a token in a URL with a shorter life) were rejected. This retires the "still to be decided" SSE-auth line in `docs/architecture.md`.
12. **Ingest runs, conflict copies, and pending Revisions live in `queue.sqlite`.** Each run — timestamp, the four counts, per-file outcomes, which Unmatched rows it raised — is what the notification shows and what "what did the last Ingest do to this Source" answers; the Unmatched rows themselves stay in the sidecar, so Loose Ends never reads a run. One JSON file per run was rejected (a folder that grows by one file per iPad return, and nobody repairs a run by hand); memory-only was rejected (the conflict-copy list would be re-fingerprinted on every open).
13. **A PDF with no Source is a Loose End, not a Source.** A PDF that no `pdf:` names is listed under *Unfinished reading* — *attach to a stub* sets `pdf:` and the first Ingest runs; *create a Source* does the same via a new note — and until then it is neither ingested nor indexed. Creating the Source from PDF metadata was rejected: the metadata is wrong often enough to mint bad citekeys, and a citekey is the one identifier links carry (ADR 0006 decision 3). Nothing about a Source exists before its note does.
14. **A PDF that goes missing is one event, not fifty.** When the file a Source's `pdf:` names is gone and no rename paired it, the Source is a Loose End under *Broken plumbing*: *locate* (pick a file; the fingerprint must match or the pick is refused as a different document) or *detach* (clears `pdf:`; the Source is a stub again; its `## Annotations` and sidecar stay exactly as they were, frozen, so every `[[klinzing2019#^h12]]` keeps resolving). Treating the disappearance as every annotation going Unmatched was rejected — the Tombstone rule already says the app never removes a link target because the world moved.
15. **Two watches, one followed symlink.** Verified: a recursive watch on the vault root does not see writes inside `sources/pdf` when that folder is a symlink to iCloud or Dropbox. So the watcher is two `fs.watch` calls — the root, and `realpath(sources/pdf)` whenever it resolves outside the root, its events rebased onto `sources/pdf/…`. Every other symlink inside the vault is not followed, matching #105's scan rule; the PDF folder is the one deliberate exception and is named as such.
16. **Lifetime, dot-entries, and no `schema` bump.** The watcher is one object owned by the vault service, created by `open` and torn down by the next `open` or exit; entries beginning with `.` (`.vitrine/`, `.obsidian/`, `.git/`) are dropped at the event level, so `index.sqlite` churn never echoes. The new sidecar and `queue.sqlite` fields do not bump `schema` in `vault.json`: no slice has yet written anything under `.vitrine/` to a real vault, and until a release freezes schema 1, additive changes fold into it.

**Update 2026-09-20 (beat 1b grill).** Decision 9's "Notes and PDFs only" restricts what a pairing *does*, not what is paired: every file is paired by hash within a batch, and every pairing is reported as `renamed` on `vaultChanged`, so a surface holding a path — the Inbox's selection, later the Vault editor's open file — follows a rename of an app-owned Kind too. Decision 5's run window is PDF-only: a Markdown batch closes at settle, since the index sends no notification to batch for. Decision 11's `vaultChanged` payload is `{ changed[], removed[], renamed[] }` and a `vaultStatus` event joins the union. `docs/architecture.md` § Watcher and Ingest.

**Update 2026-09-21 (#189).** Pairing every file by hash needs a hash for every file, so decision 4's record now lives in `files` for a non-Markdown file too — beside the sidecar's, for a PDF, once beat 5 writes one. Decision 6's eviction test (`blocks === 0 && size > 0`) is applied at once to non-Markdown files, so the sweep never materialises an online-only file to hash it; an evicted file carries its path alone until its bytes are on disk. Markdown is always read. A consequence: a changed PDF raises `vaultChanged { changed }` from this ticket on, though nothing consumes it until Ingest.

## Considered options

- **`@parcel/watcher`.** Rejected, decision 2: a native module for a distinction the pipeline discards.
- **chokidar.** Rejected: v4 dropped its fsevents dependency and sits on `fs.watch` anyway.
- **A periodic timer as the safety net.** Rejected, decision 3.
- **A manual "Ingest now".** Not considered an option: the brief says triggered by the file, never by the user, and the focus sweep is what "on return" costs.
- **Always hash, no stat shortcut.** Rejected, decision 4 — it materialises evicted files.
- **An "expected writes" registry for own-write recognition.** Rejected: it has to be right about timing; the hash comparison does not.
- **Ingest per file as it settles.** Rejected, decision 5.
- **Materialise evicted PDFs proactively.** Rejected, decision 6.
- **Ingest a conflict copy as a new Source; merge annotation sets automatically.** Both rejected, decision 7.
- **`Q:` on first Ingest only.** Rejected, decision 8.
- **Pair renames by inode.** Rejected, decision 9.
- **Splice an external Revision on settle.** Rejected, decision 10.
- **Cookie or one-shot ticket for the SSE subscription.** Rejected, decision 11.
- **A subscription per concern.** Rejected, decision 11.
- **Run records as files under `.vitrine/ingest/`, or in memory only.** Rejected, decision 12.
- **Create a Source from PDF metadata.** Rejected, decision 13.
- **A vanished PDF makes every annotation Unmatched.** Rejected, decision 14.
- **One watch, requiring the PDF folder to be a real directory.** Rejected: contradicts ADR 0006 decision 7.
- **Sweep the whole vault on focus.** Rejected: tens of thousands of stats per Cmd-Tab, for edits FSEvents already delivered.
- **Bump `schema` now.** Rejected, decision 16.
- **A `prototype/` branch first.** Not needed: the two unknowns that gated this (does `fs.watch` deliver through a symlinked root; does it follow a symlink inside the root) were answered with a Node script during the interview. The one runnable unknown left — the eviction tell — needs a real evicted file, which is an acceptance criterion, not a prototype.

## Consequences

- **+** The watcher has no dependency and no native code; swapping it is a re-implementation of one module behind stat-and-compare.
- **+** Own writes, sync re-downloads, and touches are all one rule (decision 4); there is no registry to keep in step with the write path.
- **+** The iPad return is one summary line and at most one panel, however many PDFs came back.
- **+** The SSE-auth question is closed on the same token the queries use.
- **−** `fs.watch` can drop events; the sweep is the guarantee, and the ADR's ordering rule (watch, then sweep) is what makes it one — a reader who inverts it in a refactor reopens a hole with no test that fails loudly unless the first ticket writes one.
- **−** The eviction tell is a heuristic until the first Ingest ticket confirms it; if `blocks` proves unreliable on a File Provider volume, the fallback is a small native or shell probe for `SF_DATALESS`, confined to the same module.
- **−** External Position edits are recorded up to 30 minutes late in the file (decision 10), by design; the pending record in `queue.sqlite` is the guarantee they are recorded at all.
- **−** `queue.sqlite`'s charter widens from "Proposals, Scout runs, triage events" to "app events that are not re-derivable"; § Vault layout says so.
- **−** A conflict copy, a Source-less PDF, and a missing PDF are three new Loose Ends rows; the brief's groups already hold them (*Broken plumbing*, *Unfinished reading*, *Broken plumbing*), so no new group.
- The first watcher ticket is Markdown-side: the Question Inbox from #105 goes live — a Question added or edited in Obsidian appears without reopening — exercising the watcher, settle window, own-write filter, rename pairing, event stream, and SSE auth with no PDF in sight. The PDF consumer (sweep on focus, eviction, conflict copies, decisions 13–14) joins with the first Ingest slice after ADR 0007's prototype (#108) passes.
