# 0015: CodeMirror 6 for the Vault editor; any file opens and its save records Revisions; "changed on disk" is a line, not a wall

**Status:** Accepted

ADR 0008 deliberately left the Vault editor unchosen, requiring only that it consume `packages/markdown`'s grammar functions and that its save be `replaceFile` — the user's own typing, whole. Wayfinder ticket #140 (map #131, beat 11; Prompt 7: "the design work here is restraint, not invention") asked which editor, how much of Obsidian the first Vault surface reproduces, and how a refused save is shown. Settled after a `grilling` + `domain-modeling` pass over research finding #133 (`docs/research/0133-vault-editor.md` on `research/vault-editor`): **CodeMirror 6**, the editor Obsidian itself is built on; **the editor opens any Markdown file in the vault**, including app-owned Kinds, and the `replaceFile` handler records the Position Revisions that save implies; and **a file that changed on disk under a dirty editor is a non-modal line with two actions**, never a modal and never a silent overwrite. The parser-feeding strategy, live-preview scope, autosave timing, pane layout, and first-slice scope are cheap to change and live in `docs/architecture.md` § Vault surface.

## Decisions

1. **CodeMirror 6, wrapped by hand.** The alternatives each fail a constraint this repo already fixed. ProseMirror, Tiptap, Milkdown, Lexical, and Slate are document-model editors: the file on disk is whatever their serialiser prints, so anything their schema cannot represent — Obsidian's own syntax, a chosen bullet character, setext headings, arbitrary whitespace — is normalised on the first save. That is the reserialisation ADR 0008 exists to prevent, moved into the editor. Monaco's decoration model cannot hide or replace a range, so Live Preview cannot be built on it, and it ships 24 MB of language tooling irrelevant to prose. CM6 hands back the exact text typed (`state.sliceDoc()`), reports changes through one facet, round-trips CRLF when told the file's line separator, and renders only the viewport, so a 1 MB note stays responsive. Obsidian's editor is CM6 and its Live Preview is a CM6 decoration layer, so "an Obsidian user can sit down and work immediately" is reachable with the same primitives rather than approximated. The React wrapper is ~40 lines of our own: `@uiw/react-codemirror` rebuilds the document string on every keystroke and drags in a theme we would fight; the code standard says no abstraction until a second use. This is the hard-to-reverse decision — CM6's extension model shapes every Vault feature after it — and the reason this ADR exists.
2. **Any Markdown file opens; app-owned Kinds included.** The vault's promise is that the app is not the only way in; refusing to edit a file the user could open in Obsidian would be the odd behaviour. So a Question, Research Question, Hypothesis, Experiment, or Source note opens in the Vault editor like a Note, its owned sections shown as the ordinary text they are, and its dedicated surface one click away. The save is `replaceFile`, whole, as ADR 0008 decision 2 fenced it.
3. **The `replaceFile` handler records Revisions itself.** A Working answer edited in the Vault editor must add a Revision like an edit anywhere else. It cannot ride the watcher's external-edit path (ADR 0013 decision 10): the watcher sees the app's own hash and no-ops, so nothing would fire and the edit would be silent — the failure the Position-history mechanism exists to prevent. So the handler runs the same per-Kind `positionsOf` diff the watcher runs (ADR 0014 decision 6), against the text last read or written, and records the Revision at once through `prependEntry`, coalescing within the 30-minute window and marking a Criterion edited after Evidence as ADR 0006 requires. This makes the handler the second writer of Position history and a load-bearing spot in the `CLAUDE.md` sense; the alternative of treating the editor's save as an external edit and waiting 30 quiet minutes was rejected because the editor knows exactly when the user typed, and a Revision that appears half an hour later reads as the app misbehaving.
4. **`replaceFile` never refuses on shape.** ADR 0008's verify step refuses a splice that broke frontmatter, changed `kind`, or duplicated an owned section. That protects the app's writes from the app's own off-by-ones; applied to the user's typing it would refuse to save prose until a heading they deleted is restored — the autosave equivalent of losing keystrokes, and something Obsidian would never do. The save lands; a file that lost its shape becomes a shape problem, partial, or unreadable row in the channel ADR 0008 decision 12 created, and derived state is computed from what parses. `kind` changed by hand is the same case: the file is re-read as found (ADR 0009). The one refusal `replaceFile` keeps is the hash mismatch, decision 5.
5. **Changed on disk is a line with two actions, and the editor stays live.** Two moments, one treatment. Before a save, the watcher's `vaultChanged` names the open file while the editor is dirty; at a save, `replaceFile` refuses on a hash mismatch. Either way the surface shows a non-modal line — *changed on disk · 2 min ago* — with *keep mine* (saves over the disk copy, `basedOn` re-read) and *take the disk copy* (reloads, the editor's text discarded). Autosave is suspended while the line shows; typing continues. A modal at save time was rejected because it arrives after the user has typed for ten more minutes on a stale base; last-writer-wins was rejected as a silent failure. *Keep mine* is the one place in the app a byte the user did not type changes, and it is the user's explicit call. When the editor is *clean* and the file changes on disk, it reloads silently — Obsidian's behaviour, and the common case (the app's own Position-history splice into a file the user has open).

## Considered options

- **ProseMirror / Tiptap / Milkdown / Lexical / Slate.** Rejected, decision 1: reserialise on save.
- **Monaco.** Rejected, decision 1: cannot hide a range; built for code.
- **`@uiw/react-codemirror`.** Rejected, decision 1; reconsidered only if a second CM6 instance with different needs appears.
- **Notes only; Kind files open read-only with a link to their surface.** Rejected, decision 2.
- **The editor's save as an external edit (pending Revision, 30-minute splice).** Rejected, decision 3.
- **Verify shape on `replaceFile` and refuse.** Rejected, decision 4.
- **A reload-or-overwrite modal at save; silent last-writer-wins.** Rejected, decision 5.
- **Outline-driven decorations from a per-keystroke micromark reparse.** Not an ADR matter — recorded in § Vault surface as the swappable alternative to the Lezer parsers; 200 ms per keystroke at 200 KB against 0.75 ms incremental decided it.

## Consequences

- **+** Familiarity is the feature, and it is the same editor engine Obsidian users already have under their fingers.
- **+** `replaceFile` remains the single whole-file write, and every byte it writes is the user's — decision 4 keeps it from ever being a wall.
- **+** Position history has no blind spot: edits in the app's surfaces, in the Vault editor, and in Obsidian all produce a Revision, by three paths that share one `positionsOf`.
- **−** Two parsers, one grammar (ADR 0008 decision 7, now concrete): the editor's Lezer inline parsers delegate recognition to `packages/markdown`, and the fixture corpus (#112) must check both parsers find the same tags and links in the same places, or the editor will colour something the index does not count.
- **−** The `replaceFile` handler is a second writer of Position history; a change to `positionsOf` or the coalescing rule must be checked against both callers, and the handler wants the "why this exists" comment the code standard asks for at load-bearing spots.
- **−** *Keep mine* can discard an Obsidian edit. The line names the time so the user can judge; there is no merge, by design.
- **−** CM6 counts every line break as one position whatever the separator, so a CRLF file's `packages/markdown` offsets do not equal editor positions. § Vault surface carries the rule (decorate from the editor's own LF text; save with `lineSeparator` set to the file's EOL) and the slice must test it.
- The Vault graph view remains fog on map #131: nothing here constrains it, and beat 11's spec scopes it to a later slice.
