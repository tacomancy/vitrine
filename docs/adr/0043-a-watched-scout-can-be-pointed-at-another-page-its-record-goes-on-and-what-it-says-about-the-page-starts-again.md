# 0043: A Watched Scout can be pointed at another page: its record goes on, and what it says about the page starts again

**Status:** Accepted

ADR 0042 decision 5 kept a Watched Scout's address on the form and left what a changed page does to the history it rests on as "its own decision". Since then the form has refused the edit (#469, narrowed by #520) while Scout Activity's row sends the researcher to it, so the page is changed in the Scout's file — which `docs/architecture.md` said to do, and which ADR 0016 decision 4 and ADR 0009 read as found. A grill on 2026-10-07 corrected the premise and found the real fault. `page_hash` is a hash of the reduced text, so a different page cannot be taken for an unchanged one. What is wrong is six reads that take "last time" from the Scout's whole history whatever page a run read — the page-unchanged lookup, the structure-change baseline, the test that makes a run Retroactive, Due, the Voice with its Warrant, and Loose Ends' *structure change detected* gate — and a form save that runs the Scout when its Query changes, which for a page spends (ADR 0040 decision 5). After a hand edit a new page that lists nothing is reported as *its structure changed*, the Scout speaks as though it had looked at a page no run has read, it waits out its cadence, and its first look arrives as ordinary finds. Each run already records the page it asked (`scout_runs.query`, queue schema 5), so the fix is a rule for which runs a read may use. It is hard to reverse in one respect, surprising without context, and has a real alternative — a changed page is a new Scout — which the grill weighed and set aside.

## Decisions

1. **A changed page is the same Scout, pointed elsewhere; a changed kind is a new one.** The form changes a saved page Scout's URL. Its name, cadence, Lane, Assigned Questions, every Proposal, triage row and stub (`origin_scout` still names it), its runs and its Accept rate go on. A paused Scout can be re-pointed and stays paused; a dropped one is edited after *restore*. Switching a saved Scout between arXiv and a page stays refused, as the form's disabled *Watching* has it: the file's keys differ in shape (`filter.query`, `search_back_to` and a date window against `source.url`), and that is a new Scout.
2. **A figure that says something about the page reads only the runs that asked the current page; a figure that records what the Scout did reads them all.** About the page: the Voice and its fault sentence, the Warrant (newest run, *parsed cleanly*, usual rate), Due, whether a run is a first look, the page-unchanged lookup and the structure-change baseline, Loose Ends' *structure change detected* gate, and the fleet's source-health counts, which are the Voices'. Of the Scout: last run, cost per run and its list, Accept rate (headline and weekly line), Candidates proposed, Review depth and age, Proposals, triage rows and stubs, and coverage gaps. The rule is also how a figure added later chooses.
3. **The current page is derived from the rows; nothing is declared.** For a Watched Scout a run belongs to its current page when the `query` it recorded equals the Scout's URL as trimmed, or is null — a run from before the column, which is never taken for an edit, as `isDue` already has it. For an arXiv Scout every run belongs: its Query is a Filter on one source, its date window carries over an edit, and saving an edited Query still runs it. The asymmetry is deliberate. Page identity is the string, so `…/pubs` and `…/pubs/` are two pages and a cosmetic edit costs one cheap first look; there is no normaliser, and since the raw string stays on the row, adding one later needs no migration. No marker goes in the Scout's file (runtime never lives there) and no counter on the rows (a declared generation can disagree with the `query` it stands for).
4. **A changed page is a first look.** Until a run has asked it, the Scout says *not yet* — *Not yet — this page has not been read; first check due now.* when earlier runs read another page, beside *Not yet — first check due now.* for a Scout that has never run — and is due at the next check. Its first run there proposes everything the page lists (ADR 0017 decision 9: a first run that records without proposing makes a Scout silent for weeks) and is Retroactive, so ADR 0042 decision 2 leaves that run's *reject this run* out of the Accept rate. Saving the change runs nothing: that run may spend (ADR 0040 decision 5). A first look that fails ends *Its page changed since it last ran cleanly.* when the Scout's last clean run read another page — the clause arXiv's `parse` sentence has for a Query — for the faults a page can cause, not for a missing or rejected key. A feed address follows the same rule.
5. **`page_hash` has nothing to invalidate.** A different page cannot match it and an identical one really is unchanged. It is compared only with runs at the same page, so the lookup, the baselines and the first look share one meaning of "this page's history"; the price is one read when a changed URL serves identical text.
6. **The structure-change test reads within the page.** With no earlier look at this page that found items, a page that lists nothing is *no listing found*, never *its structure changed*, and Loose Ends shows the generic failed-Scout row. *Structure change detected* needs an earlier clean run at this page that found items.
7. **The form writes the URL, and a hand edit gets the same rule.** `scouts.save` writes `source.url` in place, keeping comments and unknown keys; its edit path wrote none, so lifting the refusal alone would have reported success and kept the old URL. Because the rule is in the reads and not in the form, the file stays a way to change the page (ADR 0016 decision 4) and is honoured at the next read. Nothing watches the Scouts folder, and nothing is added.
8. **The change stays visible after the first look.** When the runs inside the weekly Accept-rate line's twelve weeks asked more than one page, one plain sentence beside the line says when the page last changed and that the line spans more than one. No mark and no colour (ADR 0042 decision 8): the line is the Scout's, and the sentence is a fact, not a verdict.
9. **The Scout Activity row keeps sending to the form.** ADR 0042 decision 5 stands, now with its reason: *try* — what the page lists and costs, before anything is saved — exists only on the form, and a page is the one field to try before keeping.
10. **Vocabulary.** Prose says *page* and *URL*. The form's field keeps its label *Address*, which is not an Address in `CONTEXT.md`'s sense (where the window is).

## Considered options

- **A changed page is a new Scout.** Rejected, decision 1: the likely reasons to change a page — a lab moves its publications page, a typo shows at the first check — are where it costs most (retype the Assigned Questions, strand a dropped Scout holding one 404, cut the Accept-rate line, which is how a change is judged, in two), and it would leave the file route, which is not wrong, unfixed. A different publisher is still a new Scout, by choice.
- **The refusal stays and only its sentence changes.** Rejected: the six reads stay wrong for the one route that exists.
- **A marker in the file, or a generation number on the runs.** Rejected, decision 3: declared state that can disagree with the rows, when the fact is already the run's `query`.
- **Scope every figure to the page,** restarting the Accept rate, cost and Candidates proposed at a change. Rejected, decision 2: they record what the Scout did and was judged on, and the line is how to see whether the change helped.
- **Scope nothing.** Rejected, decision 2: the false *structure changed*, the Warrant about an unread page and a wait of a whole cadence.
- **Normalise the URL.** Rejected, decision 3: a second definition of "the same page" to keep, to save one cheap read on a rare edit.
- **Run a re-pointed Scout on save, as an arXiv Query edit does.** Rejected, decision 4: that run is not free (ADR 0040 decision 5).

## Consequences

- **+** The one route that exists, the file, is right; the form can offer the edit because the refusal protected nothing.
- **+** A lab that moves its page is one edit, and a typo found at the first check does not strand a Scout.
- **+** Nothing is stored or declared to track the change, so the Queue, Loose Ends, Scout Activity and Home cannot disagree about it.
- **−** One-way: a re-pointed Scout's Accept rate, Candidates proposed and cost span its pages for good, and nothing splits them afterwards. The line says so, and each point keeps its `n`.
- **−** A Scout's finished runs now have two readers, the page's and the Scout's, and a figure added later must choose; decision 2 is how.
- **−** A cosmetic edit of a URL, or identical text at a new one, costs one read, which for a page with no feed is a model call.
- The spec (#563) carries: the page-scoped reader and its six call sites; `scouts.save` writing the URL and running nothing for a page; the first-look Voice sentence, the fault clause and the first run's Retroactive flag; the Loose Ends gate; the weekly line's sentence, as a separable ticket; the form's two sentences; the removal of the *until the first ticket lands* clause in `docs/architecture.md`; and the closing demo.
